# DEB 20.0.0+2 — 5 ноября 2026

Мажорный выпуск поверх `40474ed6`. Исходное рабочее дерево было чистым,
production-версии — `19.0.0+7`. Штатный генератор подготовил `20.0.0`.
Первая сборка `20.0.0+1` остановилась на старом ожидании количества пакетов
в тесте очереди анализаторов: после исключения `autover` осталось девять
пакетов вместо одиннадцати. Ожидание исправлено, все 12 адресных тестов
сборочных команд прошли. Повторный `deb_factory/build.sh --no-color --no-progress`
собрал `20.0.0+2` за 213,2 с. Build-номер после отказа не откатывался.
[Changelog](../../../changelog.md), [порядок выпуска](../../releasing.md).

## Состав и совместимость

Добавлены [ночной режим и внешняя освещённость](../../screen-presence.md#ночной-режим-и-внешняя-освещённость):
расписание, условия OR/AND с темнотой, ручное включение, отдельное разрешение
автопробуждения и MQTT-диагностика. Показания имеют целочисленные пороги и срок
актуальности от получения MQTT-сообщения; по умолчанию 1800 секунд.
Ночной запуск скрывает содержимое всех маршрутов рамки.

Снимки состояния требуют новые поля ночного режима и часов устройства;
старые снимки без них отклоняются. Backend и панель должны использовать
согласованный контракт. Вместо прежнего manual-lock передаётся
`autoWakeEnabled`; MQTT разделяет переключатели экрана и автопробуждения,
публикует фактическое питание и фазу, игнорирует retained-команды переключателей.

[Пульт рамки](../../config-app-device.md) объединяет состояние, паузу, меню
и экран, сохраняет видимость ограничений пробуждения и раскрывает подробности.
Ошибки ночных настроек показываются у соответствующих полей.
[Галерея](../../gallery.md#скрытые-файлы) подтверждает скрытие и возврат
в показ в сетке и просмотрщике. Linux-discovery разрешает адрес без ожидания
неиспользуемого TXT, повторяет один таймаут Avahi в 12-секундном окне
и сохраняет известные рамки при незавершённом resolve.

## Проверки

Полный штатный конвейер завершён: ARM64 AOT для CPU pi4, web Wasm с JavaScript
fallback, все девять анализаторов с `No issues found` и **1994 теста**:
common 41, RPC-генератор 23, backend 873, i18n 3, системные виджеты 10,
frontend 347, config_app 582, сборочные тесты tools 115.
Пропусков, ошибок и незавершённых тестов нет; JSON-профиль подтверждает полноту
release scope. Весь пакет tools отдельно не запускался.

Список анализаторов приведён в соответствие с `AGENTS.md`: служебный `autover`
и его example исключены из анализа, генерация версий сохранена.
Обновлены существующие проверки состава и очереди; политика диагностик
не ослаблена. Lock-файлы path-зависимостей синхронизированы через
`pub get --offline`, сторонние зависимости не обновлялись.

При ревью логов проверены `NightModePolicy`, `ScreenService`, `MqttService`,
`WakeSettingsCubit`, `DeviceBloc` и подтверждения галереи: значимые переходы,
начало/итог, отказ и отмена, исходные исключения и стеки. Соответствующие
регрессии и консольный обработчик common входят в прошедший набор.

Сверены руководства ночного режима, пульта, галереи, выпуска и открытые планы.
Исторические A/B и известные ограничения доступности старых материалов из
[предыдущей записи](release-19.0.0.md#проверки) не переобозначены как новая
аппаратная приёмка; старые отчёты и архивы не менялись.
В README tools ссылка на удалённый локальный отчёт smoke заменена ссылкой
на проверенный сохранённый файл в commit `fee779ff`.

Проверены Package/Version/Architecture/Description, обе production-версии,
ApplicationInfo, staging control и файл установленной версии. Все 144 MD5
содержимого DEB совпали. SHA-256 упакованного flutter-pi совпадает со входом
сборки и выпуском 19.0.0+1. Локальные ссылки изменённых руководств,
записи выпуска и индекса проверены.

## Границы приёмки

DEB не установлен на фоторамку и не опубликован в OTA. Браузерные,
аппаратные проверки и сборка Android APK не выполнялись. Версия Android
в `config_app/pubspec.yaml` сохраняется от предыдущей сборки APK;
`build_android.sh` возьмёт актуальную версию из backend при следующем запуске.
Hot reload не требовался: production-код изменён только в метаданных версии,
а правка Dart-конвейера проверена как CLI.

Локальные VM-тесты не подтверждают физические GPIO/DPMS, отсутствие вспышек
ночного старта и FrameTiming на RaPi5. Следующий отдельный прогон описан в
[сценариях ночного режима и экрана](../../screen-presence.md#проверки-на-физической-рамке).
Приёмка двух физических рамок остаётся в [плане LAN-discovery](../../plans/lan-frame-discovery.md),
аппаратная приёмка галереи — в [её руководстве](../../gallery.md#открытая-приёмка).
