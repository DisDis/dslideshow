Историческая запись двух этапов обновления, начатого 23.10.2026.
Числа тестов, зависимости и ограничения ниже относятся к соответствующему
этапу; это не инструкция для текущего checkout и не новая проверка на 29.10.2026.
Полная Wasm-сборка появилась позднее: см. [запись DEB 15](releases/release-15.0.0.md).
Актуальные команды находятся в [README приложения](../../dslideshow_flutter/README.md),
открытые предложения — в [общей очереди](../plans/roadmap.md).

## Повторное обновление на Flutter 3.47.7

После обновления SDK до Flutter 3.47.7/Dart 3.13.5 зависимости пересмотрены
повторно. Основные пакеты теперь требуют Dart >=3.13, Flutter-пакеты —
Flutter >=3.47. Версии самого приложения не увеличивались.

Обновлены pubspec и lock-файлы, модели перегенерированы. Убраны `final` у
параметров функций/конструкторов: этот синтаксис не поддерживается Dart 3.13.
Адаптировано новое имя `Ionicons.logoAndroid`.

Device Preview 3 подключён через binding перед `WidgetsFlutterBinding`,
сохранён профиль PhotoFrame 2560×1600. Его управление перенесено самим пакетом
в Flutter DevTools; прежний виджет-обёртка больше не используется.
Для embedded/release preview не включается.

Обычная AOT-генерация моделей теперь проходит: ограничение `source_helper <1.4.0`
и флаг `--force-jit` удалены. Проверены 42 Dart/Flutter-теста, 6 регрессионных
проверок Linux, генерация четырёх пакетов, Linux debug/release и web release.
Debug-запуск с новым Device Preview дополнительно проверен в Xvfb на временной
коллекции: приложение доходит до показа изображения. Проверка не открывает окно
на рабочем столе и не использует пользовательскую коллекцию.
WebAssembly dry-run теперь проходит; полноценная Wasm-сборка не проверялась.

`flutter pub outdated` не показывает устаревших прямых зависимостей у обоих
приложений. В backend `mime` остаётся 1.0.6: актуальный
`shelf_virtual_directory 3.0.1` требует `mime ^1.0.1`. Локальные fork-зависимости
сохранены. Зависимости autover уже были актуальны. Остальные разделы об
ограничениях SDK 3.38.5 ниже описывают первый проход и являются историей проверки.

## Первый этап на Flutter 3.38.5 / Dart 3.10.4

## Что изменено в этом обновлении

* Обновлены доступные совместимые зависимости семи Dart/Flutter-пакетов,
  включая `video_player 2.11.1`, `flutterpi_gstreamer_video_player 0.2.0`,
  `file_picker 13.1.0`, `font_awesome_flutter 11.0.0`, `google_fonts 8.2.1`,
  `get_it 9.3.0`, `mqtt_client 10.13.0` и генераторы моделей.
* Код выбора файлов переведён на новый API; содержимое выбранного web-файла
  читается через async `readAsBytes`. Иконки Font Awesome отображаются через FaIcon.
* Для Flutter-приложений заданы требования Dart >=3.10/Flutter >=3.38,
  Native Assets включены на уровне проекта. Глобальные настройки SDK сохранены.
* Явно объявлены используемые ранее транзитивные импорты common/backend/панели.
  Lock-файлы приложений, backend и autover больше не исключаются из Git.
* Linux runner включён в исходники; исправлены порядок поиска GTK и обновление
  результатов pkg-config. Устаревший кэш не должен повторно давать удалённые пути.
  Отсутствующие реальные headers не скрываются; CMake объясняет, что восстановить.
* `build_linux.sh` выполняет настоящую desktop-сборку и не меняет версию проекта.
  Добавлены регрессионные проверки CMake-кэша, отображения OS-иконок и upload.
* Для генерации Flutter-моделей используется `--force-jit`: AOT-компиляция
  генератора в Dart 3.10 несовместима с native build hooks. Веб-тесты используют
  `flutter_test`; лишняя прямая зависимость `test` ограничивала analyzer и Freezed.
* Исправлено обнаруженное существующими тестами распознавание мусорного вывода
  `ifconfig` как сетевых интерфейсов.

Детали сборки и команд: [инструкция](../../dslideshow_flutter/README.md).

## Почему обновлены не все пакеты до абсолютного latest

Установленный SDK — Flutter 3.38.5/Dart 3.10.4. Например, `video_player 2.14.1`
требует Dart ^3.12 и Flutter >=3.44. Другие новые версии также ограничены SDK,
пакетами Flutter SDK или генераторами. Для `json_serializable 6.14.1` обнаружен
реальный конфликт расширений с `source_helper 1.4.0`; задано `<1.4.0`.
Последние стабильные версии следует проверять снова после обновления SDK.

Локальные fork-зависимости не заменены публичными пакетами: это требует
отдельной проверки API и аппаратной совместимости. В частности, обычный
`googleapis` не является прямой заменой используемому здесь Photos-клиенту.
`permission_handler 13` поднимает Android compileSdk до 37; Android-сборка
не входит в проведённую Linux/web-проверку и потребует соответствующего SDK.

Источники: [метаданные video_player](https://pub.dev/packages/video_player),
[настройка Linux для Flutter](https://docs.flutter.dev/platform-integration/linux/setup),
[документация FindPkgConfig](https://cmake.org/cmake/help/latest/module/FindPkgConfig.html).

## Результаты проверки

* Linux x64 release собран: `dslideshow_flutter/build/linux/x64/release/bundle/`.
* Web JavaScript release собран: `config_app/build/web/`.
* Прошли тесты: common — 4, backend — 28, config_app — 3,
  system_metrics_widget — 6, приложение рамки — 1. Последний тест рамки
  остаётся шаблонным; аппаратные сценарии он не проверяет.
* Прошли 3 регрессионные проверки CMake: отсутствие GTK, некорректный include
  в pkg-config и повторная конфигурация после удаления закэшированного пути.
* Генерация моделей проверена в common/backend и обоих приложениях.
  Для веб-панели сохранено форматирование генерируемого кода через build.yaml.
* В анализе common, backend и autover замечаний нет. В приложении рамки
  осталось 10 info, в веб-панели 2 info, в метриках 1 info; ошибок и warning нет.
* `flutter pub outdated` для обоих приложений не показывает доступных более
  новых resolvable/upgradable прямых зависимостей на установленном SDK.

GTK development-пакеты в системе отсутствуют, а sudo требует интерактивный
пароль. Для проверки они скачаны и распакованы в `/tmp`, использован локальный
pkg-config sysroot и обёртки установленных Clang/GNU ld. Системные каталоги,
глобальный SDK и его настройки не менялись. Для обычной сборки установите
пакеты по инструкции в README. На физическом Pi, GPIO, DPMS и arm64 engine
проверка не выполнялась. WebAssembly не проверен: dry-run сообщает о зависимости
`flutter_keyboard_visibility_web` от `dart:html`; обычная JS-сборка проходит.
