## Завершение текущего облачного файла перед остановкой — 31.10.2026

По прямому уточнению пользователя начатое скачивание файла не прерывается
паузой, отключением аккаунта или штатным release. Файл проходит приём,
проверку целостности и локальную публикацию; следующие файлы не начинаются.
Из CloudStorage.publishDownloadedMedia удалён аргумент cancellation и мост
прерывания потока. Ошибки сети, записи, контрольной суммы и лимиты приёма
сохраняют прежнюю обработку с очисткой staging.

Яндекс отделяет остановку обхода от срока жизни текущей передачи. Обновление
access token при 401 сохранено; после остановки новый refresh не начинается.
При release OAuth и вспомогательные запросы отменяются сразу, а закрытие API
ждёт текущую передачу. Регрессия параллельного OAuth исключает позднее
подключение после начала shutdown. Ошибка ожидаемой передачи также не
пропускает освобождение API и закрытие потока сервиса.
Google Photos ждёт текущую загрузку и закрывает её HttpClient в finally;
принудительное закрытие активного клиента при release удалено.

Регрессии держат HTTP-тело открытым: пауза, отключение и release сохраняют
полный текущий файл, не запрашивают следующий и дают итог downloaded=1 без
ошибки отмены. Проверены отсутствие staging, остановка OAuth при открытом
теле, сохранение быстрого «пауза → продолжить» и почасового ожидания после
отключения аккаунта. В логах остановка прохода отличается от ошибки передачи;
успешная публикация файла не подменяется отменой.

## Остановка синхронизации на границах запросов — 31.10.2026

По следующему уточнению пользователя начатые запросы метаданных не прерываются.
YandexDriveApi.resources и YandexDriveService.withAccess больше не принимают
CloudStorageCancellation; refresh access token также идёт без токена отмены.
Обход использует текущие состояния паузы, подключения аккаунта и закрытия
Storage перед следующей страницей, подпапкой или файлом. Удалены отдельный
токен остановки прохода, active account, регистрация токенов по аккаунтам
и неиспользуемый поток отключения аккаунтов.

Быстрый pause/resume во время запроса продолжает тот же проход; постоянно
включённая пауза даёт запросу завершиться и не начинает следующий. Ответ 401
после остановки не запускает refresh. Уже начатое скачивание по-прежнему
проходит до публикации. Service учитывает реально работающие Future и при
close ждёт их вместе с текущим файлом до закрытия API. Поздний refresh после
disconnect или close не сохраняет токены и не начинает следующий запрос.
CloudStorageCancellation остался только у явно отменяемой OAuth-сессии.

Финальное ревью также обнаружило приоритет устаревшего refresh-ответа при
повторном OAuth того же аккаунта. Сравнение актуальных credentials перенесено
перед обработкой ошибки старого ответа; новые credentials имеют приоритет.
Регрессия удерживает старый refresh, успешно подключает тот же аккаунт,
затем возвращает старый invalid_grant: операция использует новый access token,
не перезаписывает его и не пишет WARNING. INFO-диагностика отличает отброшенный
