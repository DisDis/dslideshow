## Подтверждённые замечания

### R1 — P1: загрузка позволяет запись вне каталога медиа

[WebService._mediaDestination](../../../backend/lib/src/web_server/web_service.dart),
строки 448–454: `absolute(join(...))` и `startsWith` не проверяют каноническое
вложение пути. Вызов настоящего upload-handler с `filename="../escaped.jpg"`
вернул HTTP 200 и записал файл рядом с каталогом оригиналов. Операция требует
действующего кода доступа, но должна оставаться в дереве медиа, а не получать
права записи службы на другие пути. Одна нормализация строк не решит симлинки.

[Проба](probes/upload_path_probe.dart) выполняет все записи внутри собственного
временного каталога и подтверждает байты результата. Нужны отдельные регрессии
traversal, соседнего префикса, абсолютного пути и симлинков, сохраняя допустимые
подпапки. Уже находится в [общей очереди](../../plans/roadmap.md#веб-доступ-и-доверие-к-ota);
это подтверждение существующего дефекта, не новая регрессия данного снимка.

### R2 — P1: WebService записывает код доступа в INFO

[web_service.dart](../../../backend/lib/src/web_server/web_service.dart), строка 154:
`Access code updated code=$_code`; строка 286 также выводит постоянный код.
Первая запись происходит при конструировании сервиса. Журнал даёт средство
авторизации к HTTP/WebSocket, в том числе к файловым действиям. Это прямое
нарушение правила проекта о секретах в логах.

Та же [проба](probes/upload_path_probe.dart) перехватывает настоящий logger
и подтверждает присутствие синтетического кода, не печатая его значение.
Существующая проверка безопасности WebSocket-логов ограничивает выборку
категорией `WebSocketUser` и не обнаруживает эту запись категории `WebService`.
Нужно проверять серверную сессию вместе с созданием/обновлением кода.

### R3 — P1: ошибка запуска Wi-Fi-команды раскрывает пароль в logger

[wifi_service.dart](../../../backend/lib/src/service/wifi/wifi_service.dart),
строки 65–82: `Process.run` получает `psk` в аргументах, а catch передаёт
исходное исключение в `_log.severe`. При отказе запуска `ProcessException`
содержит полную команду, включая пароль. Маска `***` в исключении для ненулевого
exit code не защищает отдельную ветку отказа запуска.

[Проба](probes/wifi_log_probe.dart) с `PATH=/nonexistent` подтвердила наличие
синтетического пароля в `LogRecord.error`. Защитная проверка окружения не
позволяет выполнить `sudo`/`nmcli`; устройство не затрагивается. Нужны безопасный
тип/код ошибки и регрессия реального сервиса на этой границе запуска.

### R4 — P1: ошибка storage RPC оставляет слайдшоу в loadingNext

[slideshow_bloc.dart](../../../dslideshow_flutter/lib/features/slideshow/presentation/bloc/slideshow_bloc.dart),
строки 140, 155–162: фаза меняется до RPC; обработчика отказа, возврата в
допустимую фазу или управляемого повторения нет. Исключение из `storageNext()`
уходит из event handler, после чего guard строк 133–137 отклоняет новые
`SlideshowLoadNextEvent`. Даже явная следующая попытка не обращается к источнику.

[Проба](probes/slideshow_rpc_probe_test.dart) использует настоящий Bloc и
управляемый отказ внешнего frontend-интерфейса: ошибка наблюдается, фаза остаётся
`loadingNext`, число запросов после повтора остаётся 1. Это также пробел
диагностики: отсутствует собственный итог загрузки с безопасной причиной и
решением о повторе. Нужен согласованный путь восстановления, без превращения
отмены при закрытии в ошибку. Граница пустой/недоступной медиатеки уже открыта
в [roadmap](../../plans/roadmap.md#медиатека-и-длительная-работа).

### R5 — P2: очередь повторно запускает загрузку до первого progress

[upload_queue_bloc.dart](../../../config_app/lib/features/upload/presentation/bloc/upload_queue_bloc.dart),
строки 166–183, 211–253: выбор из `queued` запускает асинхронную работу, но слот
ещё не зарезервирован. Второе добавление до progress снова выбирает первую
задачу. [Проба](probes/upload_queue_probe_test.dart) отправила **три HTTP POST
для двух файлов**, первый файл — дважды. Fake заменяет только параметры
соединения; Bloc, файловое чтение и Dio работают настоящие, сервер — loopback.

Это нарушает предел параллелизма и может приводить к 409/429 либо повторной
публикации. Резервирование должно происходить до первого await, а слот жить
до cleanup транспорта. Дополнительные непроверенные контракты этого же
компонента — отмена при remove/close и поздние progress/result; они уже указаны
в [плане панели](../../plans/config-app-improvements.md). Массовое чтение всех
web-файлов в bytes перед запуском очереди и синхронный рекурсивный выбор папки
также требуют отдельного ограничения памяти/работы на больших коллекциях.

### R6 — P2: Update в OTA панели падает без выбранного файла

[ota_main_page.dart](../../../config_app/lib/features/ota/presentation/pages/ota_main_page.dart),
строки 114–116, 149–154: кнопка доступна до выбора файла, а callback использует
`filePath!`. [Widget-проба на en](probes/ota_selection_probe_test.dart) получила
`TypeError` до передачи события в Bloc. Отмена picker приводит к тому же пути.
Кроме того, выбранный путь и controller создаются в builder, поэтому rebuild
сбрасывает их; controller не имеет владельца disposal. Нужны состояние выбора
в Bloc, проверка доступности действия и сценарии отмены/повторного выбора.

Существующие `media_device_ui_test.dart` проверяют подписи и формат прогресса
из заранее заданного состояния. Это полезное покрытие локализации, которое
не проверяет выбор/отправку файла. Web-путь дополнительно использует `File/path`
и остаётся открытой работой; браузер здесь не запускался.

### R7 — P2: Wi-Fi RPC подтверждается до завершения системной операции

[HardwareService](../../../backend/lib/src/service/hardware/src/hardware_service.dart),
строки 435–447, сразу возвращает `EmptyResult`; `rescan`, `addWiFiConnection`
и `deleteConnection` в [WiFiService](../../../backend/lib/src/service/wifi/wifi_service.dart)
имеют сигнатуры `void ... async`. Поэтому RPC не может ожидать результат,
панель запрашивает список до завершения изменения, а отказ не передаётся
исходному запросу. Удаление дополнительно rethrow-ит ошибку из async void.

Это вывод по рабочему коду, а не аппаратный прогон. Контракт должен явно
различать приём задачи и завершение; текущая панель использует ответ для
немедленного обновления списка. Нужны управляемые системные операции,
проверка порядка ответа и передачи отказа с исходным RPC ID.

## Соответствие новым правилам и порядок следующих работ

Все найденные `RegExp` в проверенных production/test-каталогах вынесены в
`static final` или верхнеуровневые `final`; новых регулярных выражений в
продукт в этой работе не добавлялось. Современные состояния галереи/config/OTA
frontend используют Bloc/Freezed; общий `PhotoCamera` хранит скаляры, а не
неизменяемую лишь по ссылке Matrix4. Владение current/next-сессиями и отмена
подготовки подкреплены отдельными lifecycle-тестами.

Сохраняются отклонения, которые следует учитывать при содержательном изменении:
`DevicePage`/`DeviceMonitor` используют StatefulWidget/ChangeNotifier,
`ConfigScreenState` владеет черновиком и частью правил экрана;
`AppConfig`, `GalleryCatalogResult`, `GalleryImageKey`, `Effect` и ряд старых
моделей не переведены на Freezed, у двух последних равенство написано вручную.
Ресурсные владельцы/сессии не объявлялись автоматически моделями данных.
Массовая миграция существующего кода в ревью не выполнялась; предложение
общего architecture skill использовать ChangeNotifier не отменяет Bloc-правило проекта.

Приоритет следующей работы: R1–R4 с воспроизводящими регрессиями и безопасными
логами; затем закончить очередь/OTA панели и Wi-Fi RPC. После этого закрывать
пробелы фасадов, меню и форм. Уплотнение тестов — отдельный этап: сначала карта
assertions и одинаковые замеры до/после, затем точечное устранение дублей.
Общую процентную планку без учёта риска и неизвестных файлов здесь не вводили.

## Повторение диагностических проб

Пробы подтверждают **наблюдаемое дефектное поведение этого снимка**, а не
являются штатными тестами ожидаемого поведения продукта. После исправления
их assertions нужно заменить регрессиями в соответствующих `test/`.

```bash
# Из config_app/: только VM.
flutter test --no-pub ../doc/history/review-2026-10-30/probes/upload_queue_probe_test.dart
flutter test --no-pub ../doc/history/review-2026-10-30/probes/ota_selection_probe_test.dart
# Из dslideshow_flutter/:
flutter test --no-pub ../doc/history/review-2026-10-30/probes/slideshow_rpc_probe_test.dart
# Из корня; абсолютный путь Dart позволяет не запускать shell-wrapper SDK.
/home/dis/bin/flutter/bin/cache/dart-sdk/bin/dart --packages=backend/.dart_tool/package_config.json doc/history/review-2026-10-30/probes/upload_path_probe.dart
PATH=/nonexistent /home/dis/bin/flutter/bin/cache/dart-sdk/bin/dart --packages=backend/.dart_tool/package_config.json doc/history/review-2026-10-30/probes/wifi_log_probe.dart
```

Путь к Dart относится к проверенному окружению; в другом окружении передайте
свой абсолютный путь к бинарнику SDK. `wifi_log_probe.dart` специально
отказывается работать при другом PATH. Проба upload использует настоящий
handler без открытия порта; очередь использует только loopback-сервер.
