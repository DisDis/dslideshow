## Обнаружение рамок на нативном login, 30.10.2026

Проверено рабочее дерево поверх `5c7c3a6c` с реализацией discovery, до установки
нового DEB на физическую рамку. На Linux используется собственный адаптер
Avahi/D-Bus; Bonsoir после проверки освобождения ресурсов не добавлен.
Версии в рамках реализации не увеличивались; номер пакета задаёт штатная сборка.

Предрелизный `./deb_factory/run_analysis.sh --no-color --no-progress` проверил
все 11 пакетов: каждый анализатор завершился с `No issues found`, включая info.
Существующие common-тесты — 38, i18n — 3. В config_app прошли 9 проверок
discovery/login и 55 регрессий запуска/клиента/авторизации. Дополнительный EN
layout на 320 px с text scale 1.5 проверяет длинный hostname, прокрутку и выбор
адреса с нестандартным портом. В backend прошёл набор из 71 проверки discovery,
управления HTTP, галереи, потоковых загрузок и WebSocket; после заключительных
правок повторены 15 проверок discovery/HTTP control.

Изолированная тестовая D-Bus проверяет реальные рабочие адаптеры: IPv4 и SRV,
конфликт имени, предел UTF-8, ошибки, ограниченную очередь, отмену запросов и
закрытие соединения. Bloc/widget-регрессии покрывают позднюю готовность,
повтор, уход в background, совпадение текста и URI, сохранение реквизитов,
диагностику без сырых исключений и авторизованных URL. Выполнено финальное
ревью логов, гонок и владения ресурсами.

С настоящей локальной Avahi 0.8 проверены два временных сервиса на одном
Linux-хосте: разные SRV-порты, разрешение hostname/IP, HTTP по найденным
адресам и событие снятия регистрации. Нативный debug config_app собран и
запущен: автоматический поиск на login завершился, hot restart прошёл,
runtime-ошибок нет. Это подтверждает локальную интеграцию, а не работу двух
физических рамок или сети конкретного роутера. На RaPi5 ничего не устанавливалось,
браузерные проверки и сборка DEB в этом чате не выполнялись.
Оставшийся сценарий — в [плане аппаратной приёмки](../plans/lan-frame-discovery.md).

После сообщения об отказе web-сборки отдельно выполнена release-компиляция
`config_app` обычным Flutter SDK с `--no-pub --no-web-resources-cdn --wasm`:
успешно создан `config_app/build/web`, включая Wasm и JavaScript fallback.
Отказ компиляции локально не воспроизвёлся. В `tools.jsonl` последнего запуска
DEB найден отказ проверки каталога: новый discovery suite backend оставался
`unclassified`. Все три новых discovery/login suite добавлены в группу
`network`; проверка полноты каталога повторена успешно. В существующем тесте
команд сборки дополнительно проверены
исполняемый файл и рабочий каталог: `flutterpi_tool` только для
`dslideshow_flutter`, обычный Flutter SDK для web-цели `config_app`. Этот
тест прошёл. Браузер и сборка RaPi5 для этой проверки не запускались.

При следующем запуске обнаружен отдельный отказ AOT: `dbus` присутствовал в
зависимостях backend, но отсутствовал в графе `dslideshow_flutter`. Выполнен
`flutter pub get --offline` в `dslideshow_flutter`, `config_app` и `benchmarks`;
lock-файлы и `.dart_tool/package_config.json` пакетов-потребителей обновлены.
На исходниках frontend/backend `17.0.0+5` локальная команда
`flutterpi_tool build --arch=arm64 --cpu=pi4 --release` завершилась с кодом 0;
новый `dslideshow_flutter/build/flutter-pi/pi4-64/app.so` проверен как ELF64
AArch64. Повторный штатный анализ всех 11 пакетов дал `No issues found`.
Номер версии этой проверкой не увеличивался, DEB не упаковывался, устройство
не использовалось. Руководство выпуска дополнено подготовкой транзитивных

сравнивается с `ApplicationInfo.backendVersion` панели. Регрессии проверяют
красный значок/tooltip, отличия minor/build, неизвестные версии, безопасные
логи и поздний ответ от предыдущего сеанса авторизации.

На реальной рамке пользователь воспроизвёл отказ после «войти → выйти»:
`TimeoutException` разрешения адреса через 3003 мс, при найденном объявлении.
Клиент преждевременно прерывал пятисекундный resolver Avahi своим сроком
3 секунды. `ResolveService` получил 6 секунд, окно поиска — 8; управляющие
вызовы остались ограничены 3 секундами. Виртуальная регрессия принимает
ответ на четвёртой секунде и проверяет верхние сроки без реальных ожиданий.
Изолированные backend/discovery/HTTP проверки — 16, каталог групп tools — 6,
i18n — 3. Общий анализ 11 пакетов повторён до `No issues found`.
В VM отрисован реальный login с темой для визуального ревью; в нативном
config_app выполнены hot restart и проверка runtime-ошибок. Пользователь
подтвердил обнаружение рамки после исправления в сценарии «войти → выйти».
Это подтверждение одной рамки, приёмка двух устройств остаётся в плане.
Итоговые проверки discovery/login/версий — 23, включая редактируемый шаблон
и запрет входа с `xx`; ранее прошли регрессии запуска, оформления и навигации.
После последней правки поля адреса повторены анализ config_app и его 7 login
widget-тестов, выполнена release web-сборка Wasm/JavaScript. Нативный hot restart
успешен, runtime-ошибок не получено. Браузер не запускался, новый DEB не собирался.

## Задержка пробуждения, 25.10.2026

Первоначальная проверка задержки 500 мс перед `fadingIn` на Linux 25.10.2026,
рабочее дерево версии 10.0.0+2: 87 тестов backend и 60 тестов основного Flutter-приложения
прошли. Добавлено 8 backend-регрессий ожидания прогрева; проверены граница
499/500 мс, медленный аппаратный ON, дубли, повторное включение, ручная
блокировка, ошибка ON и освобождение сервиса.
Анализатор затронутых файлов, форматирование и `git diff --check` прошли.
`flutter build linux --release --no-pub` завершился успешно; результат —
`dslideshow_flutter/build/linux/x64/release/bundle/`.
Проведено финальное ревью переходов, отмены старых завершений, приоритета
ручного сна и освобождения таймера прогрева и обоих таймеров анимации.
Этот прогон не проверяет GPIO, реальное питание и FrameTiming на Pi.

На физической рамке задержки 500 мс оказалось недостаточно; значение
`ScreenService.wakeUpDelay` увеличено до 2000 мс. Регрессионные тесты используют
константу, чтобы проверять актуальную границу задержки при её настройке.
Повторный Linux-прогон 25.10.2026: все 50 тестов экрана, питания, GPIO-фильтра
и аппаратного сервиса прошли; анализатор затронутых файлов ошибок не нашёл.
Полный backend-прогон: 85 из 87 тестов прошли. Две ошибки в
`backend/test/special_screen_config_test.dart` связаны с расхождением значений
размера шрифта часов по умолчанию (20/50), воспроизводятся отдельным запуском
этого файла и не относятся к задержке пробуждения.
Достаточность 2000 мс для физического включения дисплея проверяется отдельно.

Приведённое расхождение defaults — запись об отказе того прогона, а не
утверждение о текущем состоянии `special_screen_config_test.dart`. Действующая
задержка 2000 мс задана `ScreenService.wakeUpDelay`; достаточность для конкретного
дисплея оценивается отдельным аппаратным сценарием.
