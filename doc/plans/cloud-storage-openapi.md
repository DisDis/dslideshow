# Генерация API-клиентов Cloud-провайдеров из OpenAPI

Статус: **отложено до завершения реализации и проверки Яндекс Диска в реальных условиях**.
Последняя содержательная сверка с кодом: **31.10.2026**.

Пользователь предложил заменить ручную реализацию HTTP API генерацией из
OpenAPI-файлов и сделать подход общим для будущих Cloud-провайдеров.
Текущий этап — только фиксация плана. Генератор, зависимости и клиенты
сейчас не внедряются; наличие подходящей официальной схемы Яндекса
пока не проверено и не считается установленным фактом.

## Условия начала

1. Завершена текущая реализация Яндекс Диска и пройдены локальные проверки.
2. По отдельному разрешению выполнена [живая приёмка Яндекс Диска](yandex-disk-sync.md):
   авторизация реального аккаунта, выбор папок, загрузка поддерживаемых фото/видео,
   обновление токена, повторная синхронизация и hidden.
3. Фактические результаты и найденные ограничения записаны в отчёт.

Этот план не разрешает автоматически запускать браузер или физическую рамку.

## План работ

1. **Проверить источники спецификаций.** Найти официальные OpenAPI/Swagger-файлы
   Яндекс Диска, проверить версию, лицензию, актуальность и покрытие используемых
   endpoints. Отдельно выяснить наличие схем для OAuth/Яндекс ID: один файл
   не обязан покрывать и Диск, и авторизацию. Зафиксировать пробелы схем;
   не подменять отсутствие официальной спецификации предположением.
2. **Выбрать генератор Dart-клиента.** Оценить потоковое скачивание,
   таймауты, пагинацию, авторизацию, обработку ошибок и совместимость с SDK
   проекта. Выбор делать по доступным схемам и требованиям живой интеграции.
3. **Создать общий процесс генерации.** Для каждого провайдера хранить описание
   источника схемы, закреплённую версию/контрольную сумму, версию генератора,
   параметры и каталог результата. Управляющий инструмент и проверки — Dart
   в существующем пакете tools. Внешний генератор при необходимости вызывается
   из этого инструмента. Добавление провайдера не должно требовать нового
   самостоятельного конвейера.
4. **Сохранить границы приложения.** Сгенерированный клиент отвечает за HTTP
   endpoints и DTO. Отмена OAuth меняет состояние сессии, не прерывая начатый
   запрос; поздний ответ игнорируется, а следующий запрос не начинается.
   Адаптер провайдера связывает клиент с общими Drive-моделями,
   безопасными ошибками и остановкой обхода на границах запросов и файлов.
   Начатый запрос метаданных и файл завершаются перед закрытием ресурсов.
   CloudStorage продолжает владеть импортом,
   локальной публикацией, расписанием и ресурсами. Токены остаются вне AppConfig.
   Проверка images/hidden выполняется до вызова сгенерированного download API,
   чтобы существующие файлы не передавались по сети повторно.
5. **Перевести Яндекс на сгенерированный клиент.** Удалить вытесненный ручной HTTP
   код, не создавать aliases для старого клиента. Сгенерированные файлы
   не редактировать вручную; необходимые корректировки схемы или генерации
   хранить явно и воспроизводимо.
6. **Проверить результат.** Повторить наблюдаемые сценарии текущих API/service
   тестов с fake HTTP, проверить отсутствие секретов в диагностике, очистку
   ресурсов и воспроизводимость генерации. Согласованный живой прогон
   подтвердит соответствие реальным ответам Яндекса.

## Критерии завершения

* Для выбранных API документированы проверенные источники и границы покрытия схем.
* Одна команда воспроизводит клиент из закреплённой схемы без ручной правки результата.
* Подключение следующего провайдера описано через общий процесс и его настройки.
* Ручной клиент Яндекса заменён, бизнес-логика и секреты не перенесены в generated код.
* Анализатор, релевантные тесты и отдельно разрешённая живая приёмка пройдены.
* Действующие команды перенесены в README tools/руководство CloudStorage;
  результаты — в датированный отчёт. После переноса сведений этот план удаляется.

Открытые решения: наличие и полнота схем, генератор, формат описания провайдера
и перечень ручных адаптаций. Они выбираются на этом этапе после живой проверки
текущей реализации, без предварительного расширения нынешней задачи.
