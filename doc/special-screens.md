# Специальные экраны слайд-шоу

`SlideShowConfig.specialScreens` — список самодостаточных экранов, вставляемых
между фотографиями и видео. Поддерживаются часы (`clock`) и камеры (`cameras`).
Погода пока не реализована. По умолчанию список пуст, старые конфигурации
сохраняют прежнее поведение.

[Исследование недоступной камеры и timeout RPC/MQTT](camera-rpc-investigation-2026-10.md)
содержит разбор изолятов, локальные сетевые пробы и диагностику работающей рамки.

## Настройка в config_app

Откройте **Настройки → Слайд-шоу → Special screens**. В списке можно добавить
несколько экранов одного типа, включать и выключать их, менять порядок
перетаскиванием и удалять. Название служит подписью в редакторе; `id` создаётся
автоматически. Не меняйте идентификатор вручную без необходимости.

Редактор содержит предпросмотр, общие параметры показа и форму выбранного типа.
**Done** переносит изменения в черновик общей конфигурации; **Cancel** и возврат
назад отбрасывают изменения этого редактора. Изменения списка экранов остаются
в общем черновике. Общая кнопка **Save** записывает конфигурацию на устройство.
Как и для остальных параметров слайд-шоу, для применения сохранённого файла
перезапустите приложение фоторамки через раздел управления питанием.
Уход со страницы настроек и закрытие/обновление вкладки учитывают также
изменения открытого редактора до **Done**; браузерный диалог зависит от
политики браузера. Подробности — в [описании черновика настроек](config-app-improvements.md#черновик-и-сохранение-настроек).

В редакторе отображаются полные действующие значения, включая дефолтные.
Файл на устройстве содержит только отличающиеся значения и обязательные
идентификаторы/адреса. Сброс параметра к дефолту удаляет его из файла при
следующем сохранении. Пустой список `specialScreens` также удаляется из JSON.

## Общие настройки и расписание

| Поле | По умолчанию | Назначение |
| --- | --- | --- |
| `id` | Обязательное | Уникальный идентификатор экземпляра |
| `type` | Обязательное | Тип экрана |
| `name` | Пустая строка | Название в редакторе |
| `enabled` | `false` | Включение экрана |
| `displayTimeMs` | `10000` | Время показа после завершения перехода |
| `schedule.type` | `everyMediaSlides` | После N обычных слайдов или `interval` |
| `schedule.count` | `10` | Число фотографий/видео между показами |
| `schedule.intervalMs` | `300000` | Интервал активного времени слайд-шоу |

Смена на специальный экран происходит на очередной границе слайдов.
Очередь медиа продолжается: `фото 1 → часы → фото 2`.
Каждый экран имеет собственные счётчики. Специальные экраны не увеличивают
счётчик обычных слайдов. Между двумя специальными экранами показывается
обычный слайд. Одновременно ожидающие экраны обслуживаются по очереди;
порядок списка задаёт их начальную очередность.

Пауза и выключенный экран исключаются из активного времени. Пауза удерживает
текущий слайд; часы и кадры выбранной камеры продолжают обновляться.
Выключение экрана останавливает обновления и отменяет запросы снимков.
Подготовленный следующий слайд ждёт снятия паузы. Переход также приостанавливается
при паузе или выключении экрана и продолжается с той же позиции. Если экран
выключился во время подготовки камер, подготовка отменяется и повторяется
после пробуждения с той же камеры.
Экран, который нельзя подготовить (например, с пустым списком камер),
пропускается с отсрочкой до следующего интервала. Недоступные снимки
непустого экрана камер отображаются заглушками.
Счётчики и позиции камер существуют только во время выполнения; после
перезапуска отсчёт начинается заново.

## Часы

Настройки находятся в `options` экрана `clock`:

| Поле | По умолчанию | Значения |
| --- | --- | --- |
| `timeFormat` | `h24` | `h24`, `h12` с AM/PM |
| `showSeconds` | `false` | Показывать секунды |
| `showDate` | `true` | Показывать дату |
| `showWeekday` | `false` | Показывать текущий день недели независимо от даты |
| `dateFormat` | `dd.MM.yyyy` | Также `yyyy-MM-dd`, `dd/MM/yyyy` |
| `timeFont` | `system` | Шрифт времени: `system`, `roboto`, `orbitron`, `righteous`, `fredoka` |
| `dateFont` | `system` | Независимый шрифт даты и дня недели, те же варианты |
| `timeFontSizePercent` | `50` | Процент от меньшей стороны экрана, 0 < значение ≤ 100 |
| `dateFontSizePercent` | `5` | Независимый размер даты и дня недели, в тех же единицах |
| `textColor` | `ffffffff` | ARGB, восемь шестнадцатеричных цифр |
| `backgroundColor` | `ff000000` | ARGB |

В редакторе цветов доступны ColorPicker с прозрачностью и ручной ввод
AARRGGBB. «Применить» меняет черновик, «Отмена» сохраняет предыдущий ввод;
запись экрана в общий черновик выполняется кнопкой «Готово».

Используются локальные время и часовой пояс устройства показа; в предпросмотре —
время компьютера с config_app. Обновление происходит на границе секунды или
минуты в зависимости от формата. Дата автоматически меняется в полночь.
Если текст не помещается, весь блок пропорционально уменьшается.
День недели выводится отдельной строкой; он может быть включён при скрытой дате.
Язык названий дней на фоторамке выбирается по системной локали (русский или
английский), в предпросмотре — по языку панели. Выбор языка панели не меняет
системную локаль фоторамки.

`system` сохраняет прежний шрифт. Roboto, Orbitron, Righteous и Fredoka One
используют уже включённые в проект файлы шрифтов; загрузок из сети нет.
Для символов, отсутствующих в декоративном шрифте, используется встроенный
Roboto с кириллицей. Шрифты времени и даты выбираются отдельно и сразу видны
в предпросмотре. Неизвестное имя шрифта в JSON возвращает `system`.

## Камеры

Все источники принадлежат экрану: `specialScreens[].options.cameras`.
Поддерживаются отдельные снимки JPEG/PNG по HTTP/HTTPS. Потоки MJPEG/RTSP
пока не поддерживаются. Адрес может содержать query-параметры и не обязан
оканчиваться на `.jpg` или `.png`; проверяется содержимое ответа.

| Поле `options` | По умолчанию | Назначение |
| --- | --- | --- |
| `mode` | `grid` | Все камеры сеткой или `sequence` |
| `cameras` | `[]` | Упорядоченный список камер |
| `columns` | `0` | Автоматическая компоновка; 1–16 задаёт столбцы |
| `fit` | `contain` | Изображение целиком; `cover` заполняет ячейку с обрезкой |
| `showNames` | `true` | Подписи камер |
| `refreshIntervalMs` | `5000` | Обновление снимка; `0` — только при появлении экрана |
| `requestTimeoutMs` | `10000` | Таймаут одного запроса снимка, от 100 до 120000 мс |

Камера содержит `id`, `url` и необязательные `name`, `username`, `password`.
Поддерживается HTTP Basic Authentication. В config_app камера имеет собственные
поля адреса и названия, кнопки изменения порядка и **Check snapshot**.

В режиме `sequence` первый показ выбирает первую камеру, следующий — вторую,
затем выбор повторяется по кругу. Камера остаётся выбранной на весь показ.
Если она недоступна, проверяются следующие камеры. В сетке недоступная камера
получает заглушку **Нет изображения**, остальные продолжают работать.
При ошибке или таймауте обновления ранее полученный кадр удаляется и заменяется
этой же подписью, чтобы устаревший снимок не выглядел текущим.
Если ни одна камера не ответила, непустой экран камер всё равно показывается
с заглушками; следующий успешный цикл обновления возвращает изображение.
В `sequence` при полном отказе показывается заглушка выбранной камеры.
Очередь камер продвигается только после завершения перехода на экран;
неудачная подготовка и отмена при засыпании не расходуют позицию.

Приложение показа и config_app загружают снимки **напрямую с камеры**.
Backend не скачивает и не проксирует изображения. Браузерный предпросмотр требует
доступности камеры из сети браузера и разрешения CORS на камере; HTTPS-страница
также требует HTTPS-адреса снимка. Успешность предпросмотра и доступность камеры
из сети фоторамки — отдельные проверки.

Запрос по умолчанию ограничен 10 секундами и 10 МиБ, одновременно выполняются
не более четырёх запросов на экран. В редакторе таймаут задаётся в секундах
(0,1–120), в JSON — в миллисекундах. Он включает ожидание заголовков и загрузку
тела ответа после начала запроса; ожидание очереди в него не входит. Поэтому
полная подготовка нескольких камер может длиться дольше одного таймаута.
Отсутствующее или некорректное значение в JSON восстанавливает 10000 мс.
**Check snapshot** использует тот же таймаут, что и экран; невалидный ввод
параметров блокирует проверку до исправления. Запросы не перекрывают
незавершённый цикл обновления.
При скрытии/закрытии экрана запросы отменяются, таймеры останавливаются, старые
кадры исключаются из кеша изображений. Отмена освобождает место в очереди
запросов, даже если транспорт ещё не завершил отправку. Повторная активация
уже видимого экрана не сдвигает срок следующего обновления камеры.

## Пример сохранённого JSON

Все неуказанные значения восстанавливаются из дефолтов соответствующего типа:

```json
{
  "slideshow": {
    "specialScreens": [
      {"id": "clock", "type": "clock", "enabled": true},
      {
        "id": "home-cameras",
        "type": "cameras",
        "enabled": true,
        "schedule": {"type": "interval"},
        "options": {
          "mode": "sequence",
          "cameras": [
            {"id": "entrance", "name": "Вход", "url": "http://camera-1/snapshot.jpg"},
            {"id": "yard", "name": "Двор", "url": "https://camera-2/image.png"}
          ]
        }
      }
    ]
  }
}
```

## Расширение и проверки

Модели используют Freezed совместно с `@JsonSerializable`: `copyWith`
генерируется для экранов, расписаний, настроек часов и камер. Существующий
изменяемый контракт редактора сохранён через `@unfreezed`, включая списки камер.
Определение типа экрана (`SpecialScreenDefinition`) неизменяемое и использует
`@freezed`. Для независимого черновика вложенные модели пересоздаются через
`SpecialScreenConfig.clone()`. Типы экранов, расписания, режимы и форматы — enum.
Новому типу нужны значение `SpecialScreenType`, типизированные `options`,
регистрация конфигурации/рендера и форма редактора. Планировщик и хранилища
медиа остаются общими.

Неизвестный, отсутствующий или незарегистрированный тип экрана исключается
при разборе `specialScreens` с предупреждением в журнале. Остальные экраны
сохраняют порядок и свои идентификаторы; исключённые записи не участвуют
в устранении дубликатов ID. Исходный файл при чтении не переписывается,
а при следующем сохранении неизвестных экранов в нём уже нет. Отдельный
`SpecialScreenConfig.fromJson()` для неподдерживаемого типа выбрасывает
`FormatException`; модели и хранения непрозрачных options больше нет.

В `dslideshow_flutter/lib/features/slideshow/presentation/` виджеты часов и камер
находятся в `widgets/clock_screen_widget.dart` и `widgets/cameras_screen_widget.dart`.
Реестр `widgets/special_screen_renderers.dart` связывает тип экрана, сессию и виджет.
Сессии в `sessions/` управляют таймерами, подготовкой кадров и освобождением
ресурсов независимо от компоновки интерфейса.

`SlideshowState` хранит текущий и следующий слайды в `currentSlide` и `nextSlide`.
Они могут быть `MediaSlide`, `SpecialSlide` или `null`; доступ к `MediaItem`
выполняется через `MediaSlide.item` после проверки типа слайда. Геттеров
`currentItem` и `nextItem` в состоянии нет.

Модели экранов, расписаний, настроек часов и камер удаляют собственные
значения по умолчанию прямо в `toJson()`, после штатной генерации JSON.
Генерируемый `SlideShowConfig.toJson()` вызывает эти методы автоматически;
отдельного `SlideShowConfig.toStorageJson()` и переопределения списка нет.
`AppConfig.toStorageJson()` применяет обычный `stripDefaults` ко всему JSON.
Общая функция находится в `backend/lib/src/config_json.dart` и экспортируется
из `config.dart`. Сериализация не меняет исходную конфигурацию. Обязательные
`id`, `type`, `url` сохраняются.

Локальная проверка из корня репозитория:

```sh
(cd backend && dart run build_runner build && dart test)
(cd dslideshow_flutter && dart run build_runner build && flutter test --no-pub)
(cd config_app && flutter test --no-pub && flutter build web --release --no-pub)
(cd i18n && flutter gen-l10n && flutter test --no-pub)
```

Для этой итерации согласована локальная проверка; аппаратный прогон не требуется.
Тесты используют управляемые HTTP-клиенты и изображения, проверяют отмену,
ошибки/лимиты, смену даты, очередность камер, расписание, паузу/сон при подготовке
и переходе, формы и сохранение, настраиваемый таймаут, замену недоступного кадра,
восстановление камеры, независимые шрифты, локализованные дни недели и полночь.
Реальные камеры, TLS-сертификаты и политика браузерного CORS зависят от окружения.
Для новых настроек шрифтов и состояния недоступной камеры локальные проверки
не подтверждают визуальную приёмку на дисплее RaPi5; аппаратный прогон в рамках
согласованной области не выполняется.

Проверка расширения часов и камер: 234 теста backend, 85 тестов фоторамки,
148 VM-тестов config_app, четыре Chrome-проверки и три теста локализаций
прошли. Web release панели собран; в его FontManifest проверены все четыре
встроенных семейства и файлы шрифтов. Анализаторы backend/i18n чистые,
в приложениях нет новых замечаний (остаются прежние info). Финальное
ревью кода, документации и `git diff --check` пройдены.
