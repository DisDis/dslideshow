# Новые визуальные возможности: Ken Burns, Noise Dissolve и две волны

В `dslideshow_flutter` доступны три новых перехода. Имена в JSON/API:
`noiseDissolve`, `rippleReveal`, `waterRefraction`. В исходной работе
BlurFade не менялся; [текущее расширение настроек](effect-presets-review.md)
добавляет параметры, пресеты и объединение других типов. `FixedAnimationController` остаётся
общим часом переходов: при перегрузке время увеличивается плавно, без перескока
по wall clock. Flutter-pi, прошивка, драйверы и Vulkan не менялись.

Совместимость на фоторамке:

| Возможность | Статичные фото | GIF | Видео OpenGL | Специальные экраны |
| --- | --- | --- | --- | --- |
| Noise Dissolve | Да | Да | Да | Да |
| Ripple Reveal | Да | Да | Да | Да |
| Water Refraction | Только фото → фото | Нет | Нет | Нет |
| Ken Burns во время показа | Да | Нет | Нет | Нет |

Noise Dissolve раскрывает следующий слайд мягким неоднородным шумом. Две октавы
procedural noise вычисляются шейдером; seed выбирается один раз на переход.
Одинаковый seed воспроизводит рисунок. Ripple Reveal использует круговой фронт
с концентрической волной на границе. Оба эффекта применяют GPU-маску к живому
слою: GIF и Texture продолжают обновляться, снимки этих слоёв не создаются.

Water Refraction **искажает сами пиксели** в полосе вокруг кругового фронта,
а не только меняет контур раскрытия. Источники — подготовленные `ui.Image`,
которые уже принадлежат слайдам. Повторного декодирования или framebuffer
readback в production нет. Вне полосы рисуются обычные слайды, внутри —
радиальное смещение с 16-точечной Catmull–Rom реконструкцией каждого фото.
Подготовленные фото не уменьшаются ради эффекта. Это самый затратный из новых
переходов; его стоимость измеряется отдельно, без упрощения фильтрации.

Текущий Skia/OpenGL позволяет FragmentProgram с image samplers, но не даёт
рефракции произвольного Texture-слоя через `ImageFilter.shader`. Поэтому водная
рефракция для GIF/видео отложена до отдельной работы с renderer. Не следует
подменять видео неподвижным кадром. Реестр возможностей фильтрует выбор перехода
до подготовки медиа. Если разрешена только Water Refraction, для первого слайда,
GIF, видео и специальных экранов используется Fade. Фотографии продолжают
использовать Water Refraction, когда обе стороны перехода — статичные фото.

## Настройка и предпросмотр

В панели настроек слайдшоу три перехода доступны в списке эффектов и в
предпросмотре. Предпросмотры слайдшоу и эффектов используют только встроенные
фотографии, без поля адреса видео и внешних тестовых медиа. Они работают при
недоступном frontend после загрузки панели и её assets; в Web assets приложения
могут доставляться по HTTP с того же origin. Галерея и специальные камеры
сохраняют свои сетевые источники.
У Water/Ripple «Начало волны» выбирает центр либо один из четырёх углов.
Water также настраивает силу преломления, частоту и ширину полосы; Ripple —
амплитуду, частоту и мягкость маски.
Первое появление фото в пустом предпросмотре слайдшоу использует Fade; следующая
пара показывает рефракцию. Каталог эффектов сразу начинает переход между двумя
подготовленными фото. Смена эффекта прерывает текущую демонстрацию, освобождает
отброшенные ресурсы после удаления их виджетов и начинает следующую пару.

Ken Burns — отдельная настройка **Photo motion**, а не переход. По умолчанию
выключен. Включение добавляет медленное масштабирование и панорамирование во
время показа статичного фото. Maximum zoom ограничен ×1.00…×1.15, по умолчанию
×1.06. Траектория стабильно определяется идентификатором фото. Края не оголяются.
При паузе/сне камера останавливается, при возобновлении продолжает с того же
места. Во время перехода исходящая камера заморожена; Water Refraction получает
неизменяемые параметры этой же камеры, чтобы начало волны не сбрасывало масштаб.
Входящее фото начинает движение после завершения перехода.

Для Ken Burns prepared viewport имеет запас плотности ×1.25 (на 2560×1600 —
3200×2000 при DPR 1), исходник декодируется полностью. Дополнительные пиксели
позволяют масштабировать без увеличения промежуточной картинки размером с экран.
Цена — более дорогая подготовка и дополнительные пиксели в памяти. GIF и видео
не получают движение камеры. Длительность движения задаётся `displayTimeMs`,
но bounded clock не догоняет wall clock: на загруженном GPU до смены слайда
камера может не достичь указанного максимума. Это верхняя граница масштаба.

Пример фрагмента конфигурации:

```json
{
  "slideshow": {
    "effects": {"schemaVersion": 1, "defaultDurationMs": 1000, "items": {
      "noiseDissolve": {"enabled": true},
      "rippleReveal": {"enabled": true, "options": {"origin": "topLeft"}},
      "waterRefraction": {"enabled": true, "options": {"origin": "bottomRight"}}
    }},
    "photoMotion": {"mode": "kenBurns", "maxZoom": 1.06}
  }
}
```

Отсутствующий или неизвестный режим движения означает `off`; некорректная
структура настройки также отключает движение. Некорректный zoom заменяется
на ×1.06, числовой zoom ограничивается допустимым диапазоном.
Значения по умолчанию удаляются при компактном сохранении, как остальные поля
слайдшоу. Пустые/default-записи `effects.items` могут быть опущены; пустой набор использует
служебный Fade с общей длительностью. [Формат и редактор](effect-settings.md).

## Проверки и воспроизведение

Локально, из соответствующего пакета:

```sh
# backend
 dart test test/photo_motion_config_test.dart
# dslideshow_flutter
 flutter test test/new_visual_effects_test.dart test/transition_media_selection_test.dart test/photo_motion_renderer_test.dart test/effect_regression_test.dart
# config_app
 flutter test test/slideshow_preview_test.dart
 flutter build web --release
# benchmarks
 flutter test
 flutter test tool/audit_effects_test.dart
 flutter test tool/render_effect_gallery_test.dart
```

Стенд содержит отдельные наборы:

* `config/new-visuals-controls.json`: Baseline/Fade для внешнего сравнения сборок.
* `config/new-visuals-photo.json`: новые переходы и камера, обычные/48-Мп фото,
  один прогрев и три измерения, номинал 1000 ms.
* `config/new-visuals-visual.json`: 21 контрольный кадр на эффект; SHA-256 полного
  RGBA 2560×1600 и PNG-превью. Для камеры требуется развитие движения и точное
  начало на A, а не конец на B: это движение одного фото.
* `config/new-visuals-media.json`: GIF↔фото и видео↔фото. Water Refraction и
  Ken Burns получают `unsupported` **до** загрузки неподдерживаемого медиа.
  Видео→видео здесь не запускается: это отдельная native-проверка.

`PhotoMotion-KenBurns` — только явная проба стенда; использует production
`PhotoMotionFrame`, запас prepared pixels и общий bounded clock. Это не имя
перехода для выбранного `effects.items`. Проверки production-сессии, паузы, заморозки камеры
в переходе и владения bitmap выполняются отдельно widget-тестами.

Запускать через supervisor из [аппаратного руководства](raspberry-pi-benchmarks.md):

```sh
./run-managed.sh UNIQUE_JOB --bundle /ABS/VARIANT/bundle \
  --config /ABS/VARIANT/config/new-visuals-photo.json \
  --flutter-pi /ABS/PINNED/flutter-pi --renderers opengl --timeout 3600
```

Используйте фоновый `nohup` и уникальный job, как в руководстве. Supervisor
останавливает и восстанавливает службу. Отчёты новых эффектов сравнивают их
стоимость с контролями, а не объявляют «ускорение» относительно другого рисунка.
Номинал времени и плавность оцениваются раздельно. FrameTiming raster включает
ожидание renderer/вывода, это не чистое время GPU; FPS относится к Flutter
submissions, а не измерению физического scanout.

[Аппаратные результаты и контрольные кадры](../benchmarks/reports/new-visuals-2026-10-25/report.html).
