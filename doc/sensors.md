# Температура и обороты вентилятора

Системные датчики передаются по существующей цепочке:
`sensorsScript` → строковые `SensorInfo(name, value)` → SystemInfo/RPC →
`SensorsInfoWidget`. Скрипт задаётся настройкой `sensorsScript`; штатный файл
установленного DEB — `/opt/dslideshow/scripts/sensorsScript.sh`, его источник —
[`deb_factory/template_build_arm64/opt/dslideshow/scripts/sensorsScript.sh`](../deb_factory/template_build_arm64/opt/dslideshow/scripts/sensorsScript.sh).

Каждый датчик занимает отдельную строку stdout в формате `name=value`, например:

```text
temp=57.1'C
fan1=4611rpm
```

Температура по-прежнему читается через `vcgencmd measure_temp`. Произвольные
дополнительные строки пользовательского скрипта (например, `button0=false` или
`human1=detected`) передаются прежним способом. Менять DTO или RPC не требуется.
Виджет уже распознаёт суффикс `rpm` без учёта регистра и показывает единицу `RPM`.

## Источник RPM на Raspberry Pi 5

Штатный скрипт ищет `hwmon*` в
`/sys/devices/platform/cooling_fan/hwmon/`, проверяет `name=pwmfan` и читает
`fan1_input` единственного подходящего устройства. Номер `hwmonN` не закреплён;
посторонние hwmon-устройства, в том числе другие вентиляторы, не используются.
Если найдено несколько подходящих устройств, скрипт сообщает о неоднозначности
в stderr и не выбирает произвольный источник.

`fan1_input` — показание тахометра в оборотах в минуту, см.
[документацию драйвера Linux pwm-fan](https://docs.kernel.org/hwmon/pwm-fan.html)
и [исходник драйвера Raspberry Pi 6.12](https://github.com/raspberrypi/linux/blob/rpi-6.12.y/drivers/hwmon/pwm-fan.c).
Заданный PWM и уровень thermal cooling не являются измерением RPM и для
телеметрии оборотов не используются. Подключение тахометра штатного вентилятора
описано в [документации Raspberry Pi](https://www.raspberrypi.com/documentation/computers/raspberry-pi.html#raspberry-pi-5-fans).

[Предварительное обнаружение источника 26.10.2026](history/local-checks-2026-10.md#обнаружение-rpm-26102026)
сохранено как датированное наблюдение. Номер hwmon и наличие тахометра
определяются заново при каждом запуске скрипта.

## Отсутствующие показания и ошибки

Наличие датчика проверяется по sysfs, без проверки строки модели платы.
На Pi 4 и других системах без этого тахометра строка вентилятора отсутствует.

| Состояние | stdout вентилятора | Диагностика |
| --- | --- | --- |
| Прочитано целое неотрицательное число | `fan1=<число>rpm` | Нет |
| Прочитан `0` | `fan1=0rpm` | Нет; нулевое показание допустимо |
| Нет устройства или `fan1_input` | Строки нет | Нет; датчик необязательный |
| Ошибка доступа/чтения, пустые или неверные данные | Строки нет | stderr |
| Несколько подходящих устройств | Строки нет | stderr |

Принимается одна строка из ASCII-цифр, в том числе без конечного перевода строки.
Знак, дробная часть, пробелы и дополнительные строки считаются неверным форматом.
Ошибка чтения не подменяется нулём, прежнее успешное показание не сохраняется
в новом снимке вместо отсутствующего.

Успешные непустые строки `vcgencmd` сохраняются целиком. При его ненулевом коде
вывод stdout не публикуется как измерение, stderr остаётся диагностикой. Отказ
температурного источника не мешает чтению RPM и наоборот. Штатный скрипт завершает
сбор с кодом `0`, если хотя бы один источник выдал данные; если данных нет,
возвращает `1`. Backend теперь записывает непустой stderr `sensorsScript` в warning
и при коде `0`, сохраняя успешные датчики. При ненулевом коде правило прежнее:
warning об ошибке и игнорирование всего stdout скрипта, без повторного warning.

Дополнительных таймеров и процессов для чтения тахометра нет: sysfs читается
встроенным shell `read` в уже существующем запуске скрипта. Сбор по-прежнему
использует [single-flight и секундный кеш SystemInfo](backend-performance.md#сбор-systeminfo),
frontend запрашивает сведения при запуске и раз в минуту. Удаление строки датчика
становится видно после следующего обновления снимка и интерфейса.

## Локальные проверки

Из корня репозитория, без обновления зависимостей и версий:

```bash
sh -n deb_factory/template_build_arm64/opt/dslideshow/scripts/sensorsScript.sh
(cd tools && dart test test/system/sensors_test.dart)

cd backend
dart analyze
dart test test/system_info_service_test.dart test/system_info_rpc_test.dart

cd ../system_metrics_widget
flutter analyze --no-pub
flutter test --no-pub
```

`tools/test/system/sensors_test.dart` запускает настоящий shell-скрипт с временным
деревом sysfs и подставной `vcgencmd` через PATH. Корень sysfs задаётся необязательной
переменной `DSLIDESHOW_SYSFS_ROOT` (по умолчанию `/sys`); это позволяет читать
смонтированную систему или локальные fixtures без доступа к аппаратным файлам.
Тесты проверяют положительный и нулевой RPM, отсутствие, перенумерацию и несколько
устройств, неверные данные, исчезновение файла, отказ доступа, сбой/отсутствие
`vcgencmd`, сохранность других строк, stderr и коды завершения. FIFO управляют
исчезновением и EOF без гонки по таймеру; fixture с `chmod 000` проверяет отказ
доступа от непривилегированного пользователя.

Backend-тесты проверяют частичный результат с диагностикой, смену положительного
RPM на ноль и затем отсутствие, прежнее поведение при ошибке команды и JSON
SystemInfo. Widget-тесты проверяют единицу RPM, ноль с разным регистром и удаление
вентилятора с сохранением температуры. Упаковочный тест использует маленький
fixture DEB и не собирает прошивку проекта.

## Проверка и установка на устройстве

Локальные fixtures проверяют разбор данных и ошибки, но не подтверждают
работу установленного ядра и подключённого вентилятора. Отдельная проверка
на устройстве читает показания без изменения охлаждения, PWM, GPIO, ОС,
прошивки или runtime. Если согласованы только локальные проверки, команды
устройства автоматически не выполняются.

Для отдельной ручной проверки без установки достаточно выполнить скрипт через
stdin SSH. Останавливать фоторамку для чтения sysfs не требуется:

```bash
ssh -F /dev/null -o BatchMode=yes -o ConnectTimeout=120 \
  -o ServerAliveInterval=30 -o ServerAliveCountMax=10 \
  pi@192.168.50.143 'sh -s' \
  < deb_factory/template_build_arm64/opt/dslideshow/scripts/sensorsScript.sh
```

Проверяются stdout, stderr и код завершения; для нулевого RPM достаточно
естественного нулевого показания. Не нужно менять обороты или запускать нагрузку
ради проверки. Показания при последовательных чтениях могут различаться.

Штатный скрипт поставляется в DEB; [выпуск 12.0.0](history/releases/release-12.0.0.md)
уже включает передачу RPM. Порядок последующих выпусков описан в
[руководстве](releasing.md). При ручной замене следует сохранить текущий
пользовательский скрипт, его права и путь из конфигурации, проверить кандидат
и предусмотреть возврат сохранённого файла. Формат RPM совместим с прежним
контрактом `SensorInfo`; диагностика успешного частичного сбора зависит от
установленной версии backend.
