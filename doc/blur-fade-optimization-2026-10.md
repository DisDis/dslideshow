# BlurFade: диагностика GPU-композиции на RaPi5

Продолжение [ZoomOver / BlurFade A/B](zoom-blur-optimization-2026-10.md),
25 октября 2026. Все аппаратные проверки — release, OpenGL, 2560×1600,
оригиналы JPEG 4032×3024 / 6000×4000 / 8000×6000. FixedAnimationController,
максимальная sigma=10, разрешение и качество sampling сохраняются.

## Что измеряется

Диагностика находится только в `benchmarks/lib/src/blur_probes.dart`.
`BlurProbe-*` — явный opt-in в `effects`, обычные smoke/standard их не включают.

| Вариант | Назначение |
| --- | --- |
| reference | Исходный Opacity(ImageFiltered), независимо от текущей реализации BlurFade. |
| fadeOnly | Прозрачность без blur; намеренно другой эффект, только диагностика. |
| blurOnly | Blur без fade; намеренно другой эффект, только диагностика. |
| composeDecal | Gaussian blur и последующее умножение RGBA в одном ImageFilter. |
| opacityInside | Прозрачность до blur; проверка порядка композиции. |
| noBoundary | Исходный эффект без source RepaintBoundary стенда. |
| directImage / directCompose | Подготовленный bitmap через drawImageRect с фильтром. |
| imageLayer | Подготовленный bitmap через saveLayer с фильтром и alpha. |

Прямые bitmap-пробы клонируют **handle готового ui.Image**, а не декодируют
фото заново и не снимают снимок виджета. Только статический исходящий слайд;
GIF/видео не замораживаются. Handle освобождается после отсоединения сцены.
Удаление source RepaintBoundary проверяется отдельно, поскольку в основном
слайдшоу такого явного слоя вокруг фото нет.

## Почему важен TileMode

В используемом Flutter engine `SceneBuilder.pushImageFilter` разрешает
неявный tile mode как `decal`. В `ImageFilter::initComposeFilter` вложенные
динамические фильтры разрешаются с `clamp`. Поэтому простое объединение
фильтров меняет края. Явный `TileMode.decal` сохраняет исходную обработку краёв.

Это объясняет различия предыдущего compose-прототипа; они не требовали
ослаблять blur. Источники для проверки в установленном SDK:
`engine/src/flutter/lib/ui/compositing/scene_builder.cc` и
`engine/src/flutter/lib/ui/painting/image_filter.cc`.

Нулевая sigma сохраняет обычный Opacity: замена одного fade на ColorFilter
может менять округление каналов. Проверяются sigma=0 / .01 / .1 / 1 / 2.5 / 10,
прозрачные и перекрывающиеся элементы, края и полный экран 2560×1600.

## Подтверждённые результаты

В одной release-сборке исходный `BlurProbe-reference` сравнивается с новой
реализацией BlurFade. Для каждого случая: один прогрев и три measured-повтора,
номинал 1000 ms. В первоначальной диагностике кандидат выполнялся раньше
исходного эффекта; в контрольной серии порядок обратный.

| Сценарий | Исходный, ms | Новый, ms | Wall time | Raster p95 A → B, ms |
| --- | ---: | ---: | ---: | ---: |
| photo-photo | 5149.9 | 4822.1 | −6.36% | 79.98 → 79.96 |
| large-photo | 5177.7 | 4822.2 | −6.87% | 79.98 → 79.97 |
| gif-photo | 5838.7 | 5661.0 | −3.04% | 80.01 → 79.98 |
| photo-gif | 6266.5 | 6111.1 | −2.48% | 80.03 → 79.99 |

Отдельные AOT-сборки повторно проверены в порядке **сначала кандидат,
затем baseline**, с одинаковым `blur-confirm-photos.json`:

| Сценарий | Исходный, ms | Новый, ms | Изменение |
| --- | ---: | ---: | ---: |
| photo-photo | 5166.6 | 4805.5 | −6.99% |
| large-photo | 5172.1 | 4838.8 | −6.44% |

Контроль без эффекта изменился менее чем на 0.01%. Сопоставимость конфигурации,
экрана, медиа, Flutter SDK/engine и native runtime проверяется в `analysis.json`.
Первоначальная диагностика и отдельная baseline-сборка сохраняются как
самостоятельные сырые архивы.

Улучшение умеренное, хвост raster не устранён. Число шагов контроллера,
максимальная sigma и разрешение не сокращаются. Во всех measured-повторах
сохранились монотонность и ограничение шага прогресса.

Исходная диагностика на photo-photo:

| Вариант | Средняя длительность, ms | UI p95, ms | Raster p95, ms |
| --- | ---: | ---: | ---: |
| Без эффекта | 2027.7 | .051 | 19.99 |
| Только fade | 2088.8 | .094 | 20.00 |
| Только blur | 4805.5 | .117 | 79.97 |
| Исходный BlurFade | 5133.2 | .126 | 79.98 |
| Составной фильтр | 4811.0 | .123 | 79.96 |
| Убрать RepaintBoundary | 5205.4 | .145 | 79.98 |
| Прямой drawImageRect | 5127.7 | .174 | 79.98 |
| Bitmap + saveLayer | 7022.1 | .215 | 99.98 |
| Opacity внутри blur | 7333.3 | .150 | 99.98 |

Главное ограничение — полноэкранный Gaussian blur на raster-пути, а не
построение виджетов. Время raster включает ожидания драйвера/вывода;
это **не измерение чистого GPU kernel time**. По этим данным нельзя утверждать
точное число GPU-проходов или объём видеопамяти. Большой оригинал влияет на
подготовку, но во время перехода фильтруются готовые 2560×1600 пиксели.

Новая реализация объединяет blur и последующее умножение RGBA в одном
ImageFilter. На прогрессе 0 фильтр выключен; при maxSigma=0 оставлен Opacity.
**Все 21 кадр 2560×1600 нового BlurFade побайтово совпали с исходными**,
включая начало/конец и исходные A/B. У compose-пробы без отключения фильтра
в нуле отличается первый полный кадр, хотя уменьшенное превью совпадает.
Эта деталь учтена в производственной реализации.

Bitmap-варианты и перенос Opacity внутрь blur отвергнуты: они меняют пиксели
и/или ухудшают скорость. Локальные проверки включают прозрачное/перекрывающееся
содержимое и слабую sigma, поэтому совпадение одной фотографии не используется
как универсальное доказательство корректности bitmap-пути.

### Видео и ограничения

При одном декодере, по одному прогреву и три повтора каждого эффекта:

| Сценарий | Исходный, ms | Новый, ms | Изменение |
| --- | ---: | ---: | ---: |
| photo-video | 5632.9 | 5381.8 | −4.46% |
| video-photo | 6094.1 | 6032.6 | −1.01% |

Все 12 measured-повторов завершены с плавным прогрессом; SIGSEGV нет.
Разница около 1% на video-photo не считается убедительным ускорением.
Прогон в целом **неуспешен**: сохранена одна runtime-ошибка
`MissingPluginException` при `cancel` и девять сообщений `GStreamer-CRITICAL`.
Подобные сообщения встречались и в предыдущих OpenGL-видеопрогонах;
эта работа не исправляет native-видеоплагин и не маскирует ошибки.
Видео→видео не включалось в этот точечный набор.

Прошивка, ОС и flutter-pi не изменялись. Хеш рабочего runtime до/после
контролируется в отчётах. Vulkan и 24h не запускались.

Всего шесть коротких прогонов, **131 measured-повтор**, нативных падений нет.
Максимальная температура 58.95°C, `throttle_bits=0`. Измерения прогресса
прошли во всех повторах. Видеопрогон с известной cleanup-ошибкой остаётся
неуспешным, остальные пять завершены успешно. Служба фоторамки восстановлена.

Локально прошли 16 регрессионных проверок эффектов, 20 тестов стенда,
диагностический pixel audit и 13 Python-тестов. Анализатор стенда чист;
в основном приложении остаются семь прежних info без ошибок/предупреждений.

### Артефакты и следующая работа

[Подробный HTML-отчёт](../benchmarks/reports/blur-fade-2026-10-25/report.html),
JSON/CSV, исходные архивы с SHA-256, снимки затронутых исходников и журналы
локальных проверок находятся в `benchmarks/reports/blur-fade-2026-10-25/`.
Отчёт пересоздаётся `python3 analyze.py` из этого каталога. Переносимый
архив: `benchmarks/reports/blur-fade-RaPi5-2026-10-25.tar.gz` и соседний
`.sha256`. Сборка кандидата: `benchmarks/build/benchmarks-pi5-release-jyNKg9kf.tar.gz`,
на устройстве сохранена как `variants/blur-candidate-20261025/bundle`. Сырые архивы
сохраняют ошибки целиком; их не следует заменять только итоговой таблицей.

Дальнейшее существенное ускорение потребует отдельного профилирования
Gaussian blur: промежуточные поверхности, чтение/запись текстур и ожидания
на raster-пути. Текущие FrameTiming не позволяют разделить эти затраты.
Снижать sigma, разрешение, число шагов или качество sampling ради показателя
не следует. Изменения native runtime остаются отдельной будущей работой.

## Воспроизведение

После сборки и переноса пакета из [аппаратного руководства](raspberry-pi-benchmarks.md)
запускать через `run-managed.sh` с уникальным job и соответствующими аргументами:

```bash
./run.sh --config config/blur-diagnostics.json --renderers opengl --timeout 2400
./run.sh --config config/blur-confirm.json --renderers opengl --timeout 1800
./run.sh --config config/blur-visual.json --renderers opengl --timeout 1200
./run.sh --config config/blur-video.json --renderers opengl --timeout 1200
```

Служба фоторамки должна быть остановлена перед GPU-тестом и восстановлена
после него; supervisor делает это автоматически. Видео проверяется только
с одним активным декодером. Известные ошибки native cleanup сохраняются.

`blur-confirm-photos.json` позволяет повторить одну и ту же короткую матрицу
в отдельных baseline/candidate bundles. `blur-visual.json` содержит исходный,
текущий и экспериментальные эффекты; неэквивалентный диагностический вариант
не считается кандидатом на внедрение.

Визуальный аудит сохраняет 21 контрольную позицию и два эталонных кадра.
Помимо PNG-превью 320×200, `audit/*.json` содержит `full_frames`: размер и
SHA-256 всех raw RGBA каналов **полного кадра**. Одинаковый хеш означает
побайтовое совпадение захваченных кадров. Readback выполняется вне измерений.
Это проверка Flutter-композиции, физический scanout отдельно не измеряется.

Локально:

```bash
(cd dslideshow_flutter && flutter test --no-pub test/zoom_blur_effect_test.dart test/effect_regression_test.dart)
(cd benchmarks && flutter test --no-pub)
(cd benchmarks && BLUR_PROBE_PIXELS=/tmp/blur-probe-pixels.json flutter test --no-pub tool/audit_blur_probes_test.dart)
```

Диагностический pixel audit выводит различия намеренно отличающихся проб;
его успешное завершение само по себе не означает визуальную приёмку всех проб.
