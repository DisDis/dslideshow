# Загрузка медиа и OTA

Точка входа — [разработка проекта](../readme.md#разработка).

Этап согласован 26 октября 2026 года. По уточнению пользователя проверка
безопасных путей отложена: прежние правила имён, URI-декодирования, вложенности
каталогов и работы с симлинками в этом этапе не пересматриваются. Изменения
выбора файлов в `DiskStorage` также не входят в задачу. Аппаратные прогоны и
деплой для этого этапа исключены пользователем; приёмка выполняется локально.
В частности, сохранено прежнее повторное `Uri.decodeFull` для имени медиа:
не-ASCII имена и некорректные percent-последовательности могут отклоняться.
Исправление этого поведения относится к отложенному этапу обработки путей.
Загрузка и скачивание `config.json` также остаются вне этого этапа.

## Приём и сохранение

`POST /upload/<code>/` принимает multipart/form-data с одной или несколькими
частями `file`. Каждая часть получает собственный временный `.part` в `images`
(для вложенного пути — в соответствующем подкаталоге). Файлы записываются
последовательно, с ожиданием записи, flush и close, без накопления всего тела
в памяти. Поддержка относительных подпапок существующей панели сохранена.

Публикация начинается после успешного разбора всего multipart. Переименование
в конечное имя атомарно для одного файла и заменяет прежнюю готовую копию.
Несколько файлов не образуют файловую транзакцию: если последующее
переименование не удалось, JSON ошибки содержит `published` с именами уже
опубликованных файлов. Непубликованные `.part` удаляются. Повтор одного пути
внутри запроса и параллельная загрузка того же пути отклоняются с 409.
HTTP 200 возвращается после публикации всех файлов; прежний текст успеха
`File uploaded` сохранён.

`.part` находятся внутри `images` по согласованному решению. Последующий
[этап производительности backend](backend-performance.md) исключает служебные
временные файлы загрузки из индекса `DiskStorage`; само переименование
конечного имени остаётся атомарным для одного файла.
Очистка при обрыве процесса или отключении питания не гарантируется:
автоматическое удаление оставшихся после аварии файлов в этот этап не входит.

## Пределы

| Параметр | По умолчанию |
| --- | --- |
| Полное тело media/OTA-запроса | 200 МиБ (209715200 байт) |
| Файлы в media-запросе | 100 |
| Части multipart | 128 для медиа, 2 для OTA (код и файл) |
| Текстовое поле | 1024 байта |
| Заголовки одной части | 16 КиБ |
| Активные media-запросы | 2 |
| Активные OTA-операции | 1 |
| Простой передачи | 120 секунд |
| Общая длительность приёма | 30 минут |

Предел тела учитывает фактически полученные байты, включая multipart-обвязку,
до разбора частей. Заявленный Content-Length позволяет отказать раньше,
но не заменяет счётчик. Отсутствующий Content-Length допустим.
Параметры задаются в конструкторах приёмника/сервисов; новых настроек JSON
и полей веб-панели в этом этапе нет. Исчерпание media-слотов возвращает 429
с `Retry-After: 1`; очередь тел запросов на сервере не создаётся.

При ошибке или отмене освобождаются собственные ресурсы и резервирования,
удаляются непубликованные файлы. Ошибки очистки логируются отдельно.
Недостаток места/квоты при записи или закрытии возвращает 507.
Отмена прерывает ожидание зависшей записи/открытия/закрытия. Уже начатая
операция ОС остаётся под наблюдением: закрытие выполняется после неё, а
поздно созданный временный файл повторно удаляется после завершения открытия.
Успешный ответ всегда требует завершённого закрытия; при отмене физическое
закрытие занятого файлового дескриптора может завершиться позже ответа.

## OTA

`POST /ota_upload` сохраняет существующий контракт: поле `code` перед
единственным `file`, расширение `.deb`, HTTP 200 после полного сохранения
и принятия установки. Старые клиенты и встроенная HTML-форма уже отправляют
код перед файлом. Неверный код проверяется сразу; файл до кода отклоняется
до открытия временного файла. Служебное поле также ограничено по размеру.

Временный пакет хранится в `firmwares`, закрывается и переименовывается до
передачи установщику. Автоматическое скачивание релиза использует тот же
поток сохранения, ограничения размера и неизвестной длины. HTTP-клиент
скачивания закрывается при любом результате.

Ручная загрузка, проверка/скачивание автоматического обновления, установка и
ожидание перезапуска принадлежат одной операции. Второй ручной запрос
получает 409; автоматическая проверка при занятости пропускается. Ошибочный
параллельный запрос не сбрасывает состояние действующей операции.

HTTP 200 не означает успешную установку: итог передаётся штатным `OTAInfo`.
Сохранены wire-имена enum, включая историческое `instaling`. При новой
операции очищаются прежние ошибки и exitCode. Ошибки загрузки, старта
установщика, ненулевой exitCode и ошибки перезапуска отражаются в состоянии.
Прогресс ограничен четырьмя обновлениями в секунду; переходы состояния и
финальные 100% передаются сразу. При неизвестной длине — 0% до сохранения,
затем 100%, без бесконечности и NaN.

Для ответа frontend, получения сведений о релизе, соединения и HTTP-заголовков
скачивания действует отдельный таймаут 60 секунд. При молчащем frontend
автоматическая OTA завершается ошибкой и освобождает свою блокировку.
Одновременно ожидается не более одного RPC уведомления: состояние объединяется
до последнего значения, очередь вывода установщика ограничена 64 КиБ UTF-8.
Превышающий её вывод обрезается с отдельной записью в серверный лог.
После восстановления ответов передаётся последнее ожидающее состояние.

`close()` отменяет приём, закрывает HTTP-клиенты и сервер, очищает временные
файлы и таймеры. Уже запущенный пакетный менеджер не прерывается; после
закрытия сервиса он не инициирует отложенный перезапуск службы.

## HTTP-ответы

| Код | Значение |
| --- | --- |
| 200 | Медиа опубликованы / OTA сохранена и принята в установку |
| 400 | Некорректный multipart, отсутствующий файл или неверная структура |
| 403 | Неверный код доступа или файл OTA перед авторизацией |
| 408 | Таймаут или отмена приёма |
| 409 | Конфликт пути или занятая OTA |
| 413 | Превышен предел тела, числа частей/файлов или размера служебных данных |
| 415 | Неподдерживаемый формат прошивки |
| 429 | Заняты слоты загрузки медиа |
| 500 | Ошибка сохранения или публикации |
| 503 | Закрытый сервис |
| 507 | Недостаточно места или дисковой квоты |

## Локальная проверка

Из `backend`, без обновления зависимостей:

```sh
/home/dis/bin/flutter/bin/cache/dart-sdk/bin/dart --suppress-analytics analyze
/home/dis/bin/flutter/bin/cache/dart-sdk/bin/dart --suppress-analytics test
```

Регрессии используют временные каталоги, управляемые потоки и writer с
задержкой/ошибками, а также локальный HTTP-сервер для обрыва соединения.
Проверка частоты прогресса учитывает фактическую длительность записи на диск:
не более четырёх промежуточных уведомлений в секунду плюс первое и финальное.
Отдельная синхронная проверка подтверждает объединение быстрых обновлений и
обязательную доставку итогового числа байтов без зависимости от скорости диска.
Установщик и restart подменяются fake: тесты не выполняют настоящие
`apt-get`, установку DEB, reboot или перезапуск службы. Проверяются
независимость файлов, завершение close до ответа/установки, размеры и
chunked-передача, ошибки и cleanup, слоты и конкурентные OTA-операции,
состояния, прогресс и освобождение ресурсов.

Эти проверки подтверждают контракт приёма и установки с подменённым
исполнителем. Реальная установка пакета и поведение накопителя при
аварийном отключении питания ими не проверяются.
