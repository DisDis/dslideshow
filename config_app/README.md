# DSlideshow Config

Панель настройки проекта DSlideshow. Отображаемое имя — **DSlideshow Config**:
заголовок Linux-окна, имя Android-приложения, вкладка браузера, имя установленного
web-приложения и системный заголовок Flutter. Название одинаковое для RU/EN; Flutter получает
его из `config_app_title` в ARB пакета `i18n`. Статические имена до запуска
Flutter задаются в `web/index.html`, `web/manifest.json`, Linux runner и
`android/app/src/main/res/values/strings.xml`.
В репозитории платформенные runner есть для Web, Linux и Android. При добавлении
других платформ задавайте это же отображаемое имя в их нативных метаданных.
Внутреннее имя Dart-пакета и исполняемого Linux-файла остаётся `config_app`.

Все цели `config_app` собираются обычным Flutter SDK: `flutter build web`,
`flutter build linux` и `flutter build apk`. `flutterpi_tool` применяется только к
`dslideshow_flutter` для ARM64-приложения фоторамки. При выпуске DEB из
`config_app` включается только статический web bundle `build/web`;
нативный `config_app` для RaPi5 не собирается.

Web release собирается через `./build_web.sh`: скрипт получает зависимости и
останавливается при отказе `pub get`. Если зависимости уже подготовлены,
используйте `./build_web.sh --no-pub`. Именно этот режим использует
[`deb_factory/build.sh`](../deb_factory/readme.md), запуская web-сборку параллельно
AOT и проверкам; менять зависимости во время такого запуска нельзя.

По умолчанию web release собирается с `--wasm`: Dart-код и renderer `skwasm`
используют WebAssembly в поддерживаемом браузере. Flutter также сохраняет
JavaScript/CanvasKit fallback; bootstrap и взаимодействие с браузером остаются
на JavaScript. `--no-web-resources-cdn` сохраняет ресурсы renderer в bundle.
Выбор web-окружения использует `dart.library.js_interop` и работает как с Wasm,
так и с JavaScript. Выходной каталог — `build/web`; при развёртывании копируйте
его целиком, включая `main.dart.wasm`, `main.dart.mjs` и `canvaskit/`.

Для многопоточного `skwasm` серверу нужны HTTPS (либо localhost),
`Cross-Origin-Opener-Policy: same-origin` и
`Cross-Origin-Embedder-Policy: credentialless` (либо `require-corp`).
Штатный HTTP-сервер фоторамки эти заголовки не добавляет: используется
однопоточный `skwasm`, без требования менять сервер для запуска панели.
Поддержка браузеров и ограничения — в
[документации Flutter](https://docs.flutter.dev/platform-integration/web/wasm).

Для сборки нужен Flutter 3.47+ / Dart 3.13+.

## Управление медиатекой

Состояние экранов галереи и асинхронные действия принадлежат Bloc;
экраны используют `StatelessWidget`. Локальный `AnimationController` панелей
просмотра остаётся в небольшом `StatefulWidget`. Владение ресурсами и разделение
задач описаны в [архитектуре галереи](../doc/gallery.md#состояние-панели).
Сценарии действий также проверяются по
[диагностическим логам](../doc/gallery.md#логи-управления-медиатекой);
сводки не растут построчно вместе с размером коллекции.

В галерее доступны «Медиатека», «Скрытые», «Дубликаты» и «Корзина» при поддержке API сервером.
Три файловых раздела используют общие `GalleryEntry`/`GalleryCatalog` и
`GalleryMediaSection.published/hidden/trash`. Раздел входит в ссылки на оригинал,
metadata, миниатюры и ключи кеша; viewer берёт его из `GalleryItem`.
Панель и backend используют новый общий API без перехода на старые маршруты.
Скрытие сохраняет относительный путь в `images.gallery/hidden`, исключает файл
из показа и повторной облачной загрузки по тому же пути. Доступны возврат в показ,
Undo и поиск дублей вместе с медиатекой; корзина не запрещает повторную загрузку.
Штатный объём библиотеки — **50 000+ медиафайлов**. Сетка лениво создаёт плитки,
а выбор и сверка версий работают по индексам снимка каталога; полные EXIF
и оригиналы не загружаются для всей коллекции. Текущие ограничения полного
JSON-каталога и локальных проверок — в
[руководстве больших коллекций](../doc/gallery.md#большие-коллекции-50-000-медиафайлов).
Каталог не содержит `serverId`: клиент использует контекст адреса/авторизации,
стабильные ID путей и версии stat-полей. После неизвестного результата поворота
запрашивается актуальный каталог; следующее действие создаёт новую команду.
Постоянная панель показывает счётчик (включая 0), «В корзину» и крестик;
при пустом выборе кнопки неактивны, положение сетки не меняется.
Сведения и поворот одного JPEG/PNG находятся внутри просмотра файла;
подробный EXIF не загружается для всей сетки. Перенос в корзину требует
подтверждения количества и первых 10 имён; отмена не отправляет команду.
В подтверждениях переноса и удаления каждый файл показан отдельным
пронумерованным блоком без полного пути; длинное имя переносится целиком.
В подтверждении дубликатов под именем остаётся размер файла в МБ.
Корзина хранится на рамке в `images.gallery/trash`, без автоочистки.
Доступны восстановление и подтверждаемое окончательное удаление.
В корзине есть «Выделить всё» и «Очистить корзину». Очистка подтверждается
для всех файлов снимка, независимо от выбора; новые поступления не удаляются.
Большая операция показывает прогресс по пакетам. При неизвестном ответе
оставшиеся пакеты не отправляются, список обновляется; следующее действие
проверяет актуальное содержимое. Вложенность файлов внутри `images.gallery/trash`
совпадает с `images`; manifest и история операций не сохраняются.
Уведомления имеют крестик закрытия и конечное время показа; «Отменить»
после переноса доступно 8 секунд, восстановление в корзине остаётся доступным.

Поиск выполняет Czkawka CLI на backend: панель показывает ожидание и прошедшее
время, читает итоговые группы после завершения и позволяет сравнить/выбрать
файлы вручную. Закрытие раздела не останавливает процесс.
Страница дубликатов использует компактные карточки: имя и явный чекбокс
«В корзину», фото рядом со сведениями на широком экране и вертикальная
компоновка на узком. Шапка содержит итог поиска, навигацию по группам и
«Новый поиск»; справка и успешная диагностика раскрываются отдельно.
Нижняя панель показывает количество уникальных выбранных файлов и их объём
в МБ. Новый поиск настраивается в диалоге из трёх режимов; отмена не меняет
режим и выбор. После остановки/ошибки сохраняется выбор предыдущего результата
для файлов с прежними версиями. Подробнее — в
[руководстве сравнения](../doc/gallery.md#поиск-и-сравнение-дубликатов).
Сведения смонтированных карточек (до 10 на странице) загружаются отдельно от
изображений; при ошибке показана причина и отдельная кнопка повтора сведений. Требования к серверным
утилитам — в [README backend](../backend/README.md), контракты, форматы поворота
и ограничения — в [руководстве галереи](../doc/gallery.md#управление-медиатекой).
Новые возможности проверены локальными VM-тестами; браузерная и аппаратная
приёмка этим не подтверждаются.

Просмотр показывает путь от корня `images` «хлебными крошками», сравнение — с
акцентом на ближайшую папку и раскрытием полного относительного пути.
Разрешение подсвечивается относительно всей группы; рекомендован максимум,
при равенстве — первый в списке. Его разрешение зелёное, прочие равные — жёлтые.
Карточка кандидата обведена зелёной рамкой и содержит сверху плашку со звездой.
Равные и неизвестные значения,
ограничения оценки и нейтральная отметка минимального размера файла описаны в
[руководстве сравнения](../doc/gallery.md#поиск-и-сравнение-дубликатов).
Рекомендации не выбирают файлы в корзину. После первых 10 имён подтверждение
показывает количество остальных файлов; окончательное удаление также показывает
ожидаемый освобождаемый объём. Похожий поиск на backend использует Lanczos3;
прежние результаты обновляются только новым поиском.

## Linux desktop

На login автоматически запускается поиск доступных рамок через Avahi 0.8+
и системную D-Bus. Компактная карточка содержит миниатюру, host/IP:порт
и кнопку-иконку выбора. Выбор подставляет адрес; «Повторить» сохраняет известные
рамки при ошибке обновления. В навигации показана версия подключённого backend;
несовпадение major с целью сборки отмечено красным значком с tooltip.
Настройка службы, ограничения
сети и логи — в [руководстве панели](../doc/config-app.md#поиск-рамок-на-странице-входа).
Нативные сборки Windows/macOS/iOS подготавливаются отдельно.

Из папки `config_app`:

Для видео в Linux desktop используются media_kit и системный libmpv.
Помимо GTK и инструментов сборки нужны заголовки и библиотеки:

```sh
sudo apt-get install libmpv-dev libepoxy-dev
```

```sh
./build_linux.sh --debug
flutter run -d linux
```

После добавления нативных зависимостей выполните полную пересборку и
Stop → Start отладки: Hot reload не регистрирует новый Linux-плагин.
Для запуска перенесённого bundle требуется системная библиотека libmpv
(в актуальном Debian/Ubuntu — пакет `libmpv2`).

В галерее поддерживаются запуск, пауза и перемотка видео; первый запуск
плитки начинается по нажатию, полноэкранный просмотр — автоматически. До запуска
плитка показывает серверный JPEG-постер через общий загрузчик миниатюр; на
платформе без плеера постер также доступен. Настройки генерации находятся в
`gallery` конфигурации рамки и применяются после её перезапуска.
Нажатие на изображение видео скрывает или показывает панели просмотра;
скрытые панели не блокируют кнопки плеера и перемотку.
Ошибки загрузки и инициализация дольше 15 секунд показывают локализованное
сообщение. Закрытие, смена файла и поздние ответы не запускают старое видео.
Если backend недоступен, контроллер не создаётся и панель показывает
ограничение платформы. Linux-плеер рассчитан на видеофайлы с известной
длительностью; live-потоки без длительности завершаются таймаутом инициализации.

В Web продолжает использоваться `video_player_web`: Linux/FFI-код подключается
условно и не входит в браузерную ветку. Форматы и autoplay зависят от браузера.
Проверка сборки из `config_app`:

```sh
./build_web.sh --no-pub
```

Автоматические браузерные тесты удалены из-за стоимости компиляции и запуска
Chrome. Обычные unit/widget-тесты выполняются в VM; браузерные тесты пишем
и запускаем только с согласия пользователя. VM-тесты не проверяют web-точку
входа, выбор окружения JavaScript/Wasm и DOM-событие `beforeunload`.
Правило и границы покрытия описаны в
[руководстве тестирования](../doc/testing.md#браузерные-проверки).

Если после исправления обработчика стек ошибки по-прежнему указывает на старую
строку или выражение, выполните полный Restart отладки (Stop → Start) из
каталога `config_app`. Hot reload сохраняет состояние работающего приложения;
при диагностике важно проверить, что запущен именно текущий checkout.
Для панели, которую отдаёт отдельный web-сервер или фоторамка, изменение
`lib/` не обновляет обслуживаемую сборку: нужно обновить её на этом сервере.

Для release-сборки используйте `./build_linux.sh --release`.
Скрипт проверяет инструменты, GTK и mpv/epoxy, очищает нативный CMake-кэш,
выполняет `flutter pub get` и сборку. Обновление путей GTK также работает
при обычном `flutter build linux` и запуске из VS Code. Для mpv/epoxy также
обновляются include-пути и закэшированные пути библиотек: исчезнувший временный
SDK не должен оставаться в сборке. Если системного `libmpv-dev` нет, CMake
останавливается с командой установки; очистка кэша не заменяет установку пакета.

Для отладки из VS Code откройте `lib/main.dart` этого пакета, выберите устройство
Linux и запустите F5. После изменения Linux runner выполните Stop → Start.
Отдельный pre-launch скрипт для обновления путей зависимостей не требуется.

## Android APK

Исходники Android runner хранятся в Git. Для сборки требуется установленная
Android SDK Platform API 37: `compileSdk = 37` задан в
`android/app/build.gradle.kts`, поскольку его требует `permission_handler_android`.
Локальные пути `android/local.properties`, Gradle/Kotlin/CMake-кеши, результаты
сборки, сгенерированный регистратор плагинов и ключи подписи исключены из Git.
Gradle wrapper scripts/JAR также исключены: Flutter восстанавливает их при сборке
из своего SDK; версия Gradle сохраняется в `gradle/wrapper/gradle-wrapper.properties`.

Для скрипта нужны подготовленные зависимости Dart-пакета `tools`
(`cd tools && dart pub get` из корня репозитория). Из папки `config_app`:

```sh
./build_android.sh
```

В Flutter 3.47.7 не добавляйте `--no-pub` к Android release-сборке:
после обычного `pub get` регистратор плагинов содержит dev-плагин `integration_test`,
а `--no-pub` пропускает его повторную генерацию для release. Обычный
`flutter build apk --release`, используемый скриптом, обновляет регистратор
([описание проблемы во Flutter](https://github.com/flutter/flutter/pull/194204)).

Скрипт вызывает Dart-команду `build-android` из пакета `tools`. Перед сборкой она
записывает версию из `../backend/pubspec.yaml` в `config_app/pubspec.yaml`, затем
выполняет обычный `flutter build apk --release`: для `17.1.0+1` Android получает
`versionName = 17.1.0` и `versionCode = 1`. Версия backend должна содержать положительный целочисленный
build-номер `+N`, не превышающий Android-лимит 2100000000.
Остальные поля pubspec сохраняются; Flutter получает зависимости штатным способом.
Записанная версия остаётся в `config_app/pubspec.yaml`, в том числе при последующем отказе сборки.

После успешной сборки рядом со штатным `build/app/outputs/flutter-apk/app-release.apk`
появляется `build/app/outputs/flutter-apk/config_app_<version>.apk`, например
`config_app_17.1.0+1.apk`. При отказе Flutter переименование/копирование не выполняется,
код ошибки сохраняется. Прямой вызов `flutter build apk` также использует
записанную версию из `config_app/pubspec.yaml`.
Локальный runner использует debug-подпись для release; для публикации
необходимо отдельно настроить release-подпись.

Основной Android-манифест задаёт `INTERNET` и `ACCESS_NETWORK_STATE` для всех
режимов сборки, включая release. `usesCleartextTraffic = true` разрешает
HTTP/WS-подключение к адресу фоторамки, задаваемому пользователем.
Это необходимо для штатного HTTP-сервера рамки без TLS. Подробнее —
[сетевые разрешения](https://developer.android.com/develop/connectivity/network-ops/connecting)
и [настройка cleartext](https://developer.android.com/guide/topics/manifest/application-element#usesCleartextTraffic).
Текущий `targetSdk` берётся из Flutter SDK (36); `compileSdk = 37` его не меняет.
При переходе на `targetSdk >= 37` потребуется отдельный runtime-запрос
`ACCESS_LOCAL_NETWORK` перед подключением к локальной сети
([правила Android](https://developer.android.com/privacy-and-security/local-network-permission)).
На Android рамки ищет системный NSD по `_dslideshow._tcp.`; адрес можно также ввести вручную.
На Android до API 34 поиск временно удерживает Wi-Fi multicast lock; для него объявлен
`CHANGE_WIFI_MULTICAST_STATE`. Окно поиска — 8 секунд, очередь ограничена 256 сервисами,
разрешение адресов выполняется последовательно. Завершение, уход в фон и закрытие login
останавливают NSD и освобождают lock; Linux продолжает использовать Avahi/D-Bus.

Фото и видео выбираются системным файловым диалогом. «Добавить папку» на Android
использует Storage Access Framework: приложение получает доступ только к выбранному
дереву, обходит подпапки страницами по 128 записей и читает активные файлы через
ContentResolver блоками до 64 КиБ, сохраняя относительные имена. Общие разрешения
`READ_MEDIA_*`, `READ_EXTERNAL_STORAGE` и `MANAGE_EXTERNAL_STORAGE` для этого не нужны.
Ограничения выбора системных каталогов задаёт Android; корень Download и Android/data
могут быть недоступны, но обычную вложенную папку можно выбрать. Неизвестный размер
файла показывается существующей ошибкой источника, без чтения всей папки в память.
NSD и SAF встроены в Android runner: после их изменения нужны полная пересборка,
установка APK и запуск отладки заново; одного hot reload недостаточно.
Поиск диагностируют `FrameDiscovery`/`AndroidDiscovery`, выбор и импорт — `UploadQueueBloc`.
Ошибки подключения диагностируются существующими logger `ClientService` и
`AuthenticationRepository`, получение логов — `flutter logs -d <device-id>`.

После сборки проверьте установочные метаданные и упакованный манифест:

```sh
"$ANDROID_HOME/build-tools/36.0.0/aapt" dump badging build/app/outputs/flutter-apk/app-release.apk
"$ANDROID_HOME/build-tools/36.0.0/aapt" dump xmltree build/app/outputs/flutter-apk/app-release.apk AndroidManifest.xml
```

Используйте установленную версию build-tools, если она отличается от примера.
Ожидаются имя `DSlideshow Config`, версия из `backend/pubspec.yaml`, оба сетевых разрешения
и `usesCleartextTraffic = true`. Это проверяет содержимое APK; подключение
с Android-устройства к фоторамке проверяется отдельно.

## Проверки видео

[Распределение покрытия, общие fake-зависимости и замер времени тестов](../doc/testing.md).

Unit/widget-тесты проверяют загрузку, паузу, перемотку, ошибки, таймауты,
смену URL, скрытие панелей, закрытие во время загрузки и освобождение контроллеров.
Полный набор проверок панели:

```sh
flutter test --no-pub
```

Проверки подготовки фото, повторения пары, кешированных входов и освобождения
ресурсов фотопредпросмотра, в том числе при недоступном frontend, отдельно:

```sh
flutter test --no-pub test/asset_photo_slide_session_test.dart \
  test/slideshow_preview_test.dart
```

Локализации RU/EN хранятся в ARB и обновляются штатным генератором из `i18n/`;
команды — в [README локализаций](../i18n/README.md).

Исторические исходники, сборки и [OpenGL backbuffer capture](../benchmarks/tool/egl_capture/README.md)
сохранены в архиве для воспроизводимости результатов. Локальные widget-тесты и
браузерный предпросмотр не заменяют проверку native compositor на RaPi5.

Функциональный тест Linux использует настоящий libmpv и MP4 через локальный
HTTP-сервер. Он проверяет воспроизведение и native texture, паузу, перемотку,
ошибочный URL и освобождение плееров. Путь к MP4 обязателен; без него тест
пропускается. Из `config_app`:

```sh
flutter test --no-pub -d linux integration_test/linux_video_test.dart \
  --dart-define=VIDEO_SMOKE_FILE="$(realpath ../benchmarks/assets/media/video_a.mp4)"
```

На машине без дисплея этот же тест можно запустить через
`LIBGL_ALWAYS_SOFTWARE=1 GDK_BACKEND=x11 xvfb-run -a flutter test ...`.
Это функциональная проверка desktop-плеера, а не измерение производительности
фоторамки; renderer и runtime RaPi5 она не проверяет.

Зависимости, причины ошибок `PkgConfig::GTK` и GSettings, способы диагностики
и порядок переноса исправления в другие приложения описаны в
[инструкции по Linux-сборке](../doc/linux-build-troubleshooting.md).

[Новые эффекты и Ken Burns](../doc/effects.md): настройка, совместимость,
предпросмотр, тесты и измерения на RaPi5.

[Тридцать дополнительных переходов в стиле видеоредакторов](../doc/effects.md#визуальные-варианты):
новые переходы в настройках и предпросмотре, совместимость и локальные проверки.

Сравнение дубликатов показывает список до 10 файлов на странице с чекбоксами;
все переносы в корзину требуют подтверждения. Backend исключает недоступных
участников и пропускает группы, где осталось меньше двух актуальных файлов.
Статус поиска пока содержит все найденные группы; отдельный запрос проверяет
актуальность открываемой группы. Сведения карточек загружаются лениво,
не более четырёх запросов одновременно; ожидание отменяется при закрытии.
Решения пользователя хранятся только в памяти открытого экрана.
