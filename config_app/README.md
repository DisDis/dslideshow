# config_app

Web release собирается через `./build_web.sh`: скрипт получает зависимости и
останавливается при отказе `pub get`. Если зависимости уже подготовлены,
используйте `./build_web.sh --no-pub`. Именно этот режим использует
[`deb_factory/build.sh`](../deb_factory/readme.md), запуская web-сборку параллельно
AOT и проверкам; менять зависимости во время такого запуска нельзя.

По умолчанию web release собирается с `--wasm`: Dart-код и renderer `skwasm`
используют WebAssembly в поддерживаемом браузере. Flutter также сохраняет
JavaScript/CanvasKit fallback; bootstrap и взаимодействие с браузером остаются
на JavaScript. `--no-web-resources-cdn` сохраняет ресурсы renderer в bundle.
Выбор web-окружения использует `dart.library.js_interop` и работает как с Wasm,
так и с JavaScript. Выходной каталог — `build/web`; при развёртывании копируйте
его целиком, включая `main.dart.wasm`, `main.dart.mjs` и `canvaskit/`.

Для многопоточного `skwasm` серверу нужны HTTPS (либо localhost),
`Cross-Origin-Opener-Policy: same-origin` и
`Cross-Origin-Embedder-Policy: credentialless` (либо `require-corp`).
Штатный HTTP-сервер фоторамки эти заголовки не добавляет: используется
однопоточный `skwasm`, без требования менять сервер для запуска панели.
Поддержка браузеров и ограничения — в
[документации Flutter](https://docs.flutter.dev/platform-integration/web/wasm).

[Расширенные настройки и пресеты](../doc/effect-presets-review.md): 37 семейств,
82 пресета прежних эффектов, пять точек начала Water/Ripple и таблица
визуально принятого объединения каталога. Последующее исследование
производительности — в [отчёте RaPi5](../doc/effect-performance-2026-10.md).

[Персональные настройки эффектов](../doc/effect-settings.md): новый формат
`slideshow.effects`, общая/своя длительность в мс, объединение вариантов, каталог
и предпросмотр между фотографиями с кнопкой «Повторить» последнюю фотопару.
Настройки хранятся картой с ключами `EffectType`; диапазоны и сочетания
параметров проверяет только config_app, до отправки Save.
Старые `allowedEffects`/`transitionTimeMs` не поддерживаются.

После визуальной проверки пользователь разрешил удалить все рабочие оригинальные
реализации и временный переключатель сравнения. Предпросмотр использует только
текущие эффекты с общими options/seed=42. Подготовленные фото получают `RepaintBoundary`,
как на рамке. Кнопка **Повторить**
сохраняет последнюю фотопару. Каталог остаётся 37 семейств / 82 пресета.

Предпросмотры слайдшоу и эффектов используют только встроенные фотографии из
assets панели: сторонние изображения, видео и поле адреса видео удалены.
Происхождение фотографий и исходные запросы указаны в
[описании assets](assets/preview/README.md).
После загрузки самой панели демонстрация не требует доступа к внешним медиа
или подключения frontend к фоторамке. В Web файлы приложения и его assets
могут загружаться по HTTP с того же origin; это не загрузка сторонних медиа.
Пауза, пропорции, повтор фотопары и текущие настройки эффектов остаются локальными
инструментами. Галерея и предпросмотр специальных камер сохраняют собственные
источники и правила доступа к сети.

В следующем [раунде оптимизации VHS](../doc/gpu-effect-performance-2026-10.md)
пользователь также принял ускоренный вариант визуально. Временное сравнение
с эталоном удалено вместе с переключателем. Между подготовленными фото preview
использует кешируемый tint VHS. Поддержка живых GIF/видео на фоторамке
сохраняется независимо от набора фотографий preview.

Исходники baseline, release-bundle и результаты сравнения сохраняются в
[архивном отчёте](../doc/effect-performance-2026-10.md). Ручное принятие не
переписывает статусы строгой пиксельной проверки. Web-предпросмотр служит оценке
картинки; фактическое поведение native compositor и FPS проверяются на RaPi5.

В обычном превью теперь доступны принятые быстрые реализации Stretch и CrossZoom,
а Radial Blur между двумя фото использует полноразмерный девятилучевой shader.
Замороженная исходящая PhotoMotion-камера сохраняется. Переключателя между
прежней и новой реализациями нет.

Glass и Film Dissolve между подготовленными фото также используют основные
полноразмерные фото-шейдеры, общие с фоторамкой. Различия на дробных стыках Glass и в
округлении тёмных цветов Film описаны в [отчёте](../doc/effect-performance-2026-10.md#продолжение-фото-шейдеры-glass-и-film-dissolve).

Предпросмотр и фоторамка передают всем эффектам единый `EffectSlideInput`:
сохранённое представление слайда и необязательные заимствованные пиксели фото
с неизменяемой камерой Ken Burns. Входы создаются один раз перед переходом;
дополнительные снимки и декодеры не нужны. Совместимость проверяется через
`supportsInputs`, без списка конкретных эффектов. Для несовместимой пары
сохраняется Fade с общей длительностью. Фото предпросмотра принадлежат
`AssetPhotoSlideSession`, использующей общий с фоторамкой контракт `SlideSession`:
подготовка, активность, захват входа эффекта и идемпотентное освобождение.
Сессии `_current`/`_next` и отложенное освобождение после удаления старого
представления сохраняют заимствованные bitmap до конца перехода. Ошибка,
отмена или позднее завершение подготовки не возвращают отброшенную фотопару.
Общий контракт описан в [руководстве renderer](../doc/slideshow-renderer.md).

В полях цвета перехода, фона слайдшоу и часов доступны ColorPicker с
прозрачностью и ручной ввод AARRGGBB. Кнопка палитры открывает диалог;
«Применить» меняет черновик, «Отмена» сохраняет предыдущий ввод. Пакет
[flutter_colorpicker](https://pub.dev/packages/flutter_colorpicker) — 1.1.0;
он добавлен только в панель настройки.

Панель настройки фоторамки. Для сборки нужен Flutter 3.47+ / Dart 3.13+.

[Телеметрия и управление фоторамкой](../doc/config-app-device.md): системные
показатели, датчик присутствия, сведения о дисплее и версиях рамки; пауза,
меню и ручное включение/выключение экрана через авторизованный WebSocket.
В телеметрии также доступны заполненность RPC-пулов, ожидающие запросы,
скорости и время обработки по направлениям между сервисами.

[Галерея: миниатюры, загрузка и версии кеша](../doc/gallery.md): серверные
миниатюры в сетке, общая очередь Web/Linux с приоритетом viewport, отменой и
дедупликацией, API, бюджеты, ограничения и локальные проверки. Fullscreen и
фоторамка сохраняют оригиналы; аппаратная приёмка производительности ещё открыта.

[Подробный план реализации](../doc/gallery-implementation-plan.md): этапы,
API/revisions, владельцы состояния, отмена/дедупликация, кеши и критерии приёмки.
[Исходное исследование](../doc/gallery-performance.md) сохраняет данные baseline.

[План улучшений и локальные проверки](../doc/config-app-improvements.md):
адаптивный интерфейс, русский/английский языки, светлая/тёмная тема,
живой предпросмотр, черновик настроек, Save/Reload и защита несохранённых
правок, таймауты WebSocket/RPC и обработка разрыва соединения.

В меню **Оформление** выбираются язык и тема панели; по умолчанию используются
системные настройки. Выбор действует в текущей сессии панели и не меняет
конфигурацию фоторамки. На широком окне меню остаётся видимым слева,
на узком открывается кнопкой в заголовке. Визуальные редакторы показывают
предпросмотр рядом с формой либо над ней; его можно свернуть.

При запуске панель сразу показывает вход, если подключение ещё не
авторизовано, либо главную страницу при действующей авторизации.
Маршрут определяется по текущему состоянию подключения, даже если оно
изменилось до появления интерфейса. Автоматического восстановления сессии нет.

[Специальные экраны](../doc/special-screens.md): редактор часов и камер,
предпросмотр, отдельные шрифты времени/даты, день недели, таймаут снимка камеры,
порядок показа и компактное сохранение конфигурации.

## Linux desktop

Из папки `config_app`:

Для видео в Linux desktop используются media_kit и системный libmpv.
Помимо GTK и инструментов сборки нужны заголовки и библиотеки:

```sh
sudo apt-get install libmpv-dev libepoxy-dev
```

```sh
./build_linux.sh --debug
flutter run -d linux
```

После добавления нативных зависимостей выполните полную пересборку и
Stop → Start отладки: Hot reload не регистрирует новый Linux-плагин.
Для запуска перенесённого bundle требуется системная библиотека libmpv
(в актуальном Debian/Ubuntu — пакет `libmpv2`).

В галерее поддерживаются запуск, пауза и перемотка видео; первый запуск
плитки начинается по нажатию, полноэкранный просмотр — автоматически. До запуска
плитка показывает серверный JPEG-постер через общий загрузчик миниатюр; на
платформе без плеера постер также доступен. Настройки генерации находятся в
`gallery` конфигурации рамки и применяются после её перезапуска.
Нажатие на изображение видео скрывает или показывает панели просмотра;
скрытые панели не блокируют кнопки плеера и перемотку.
Ошибки загрузки и инициализация дольше 15 секунд показывают локализованное
сообщение. Закрытие, смена файла и поздние ответы не запускают старое видео.
Если backend недоступен, контроллер не создаётся и панель показывает
ограничение платформы. Linux-плеер рассчитан на видеофайлы с известной
длительностью; live-потоки без длительности завершаются таймаутом инициализации.

В Web продолжает использоваться `video_player_web`: Linux/FFI-код подключается
условно и не входит в браузерную ветку. Форматы и autoplay зависят от браузера.
Проверка сборки из `config_app`:

```sh
./build_web.sh --no-pub
```

Автоматические браузерные тесты удалены из-за стоимости компиляции и запуска
Chrome. Обычные unit/widget-тесты выполняются в VM; браузерные тесты пишем
и запускаем только с согласия пользователя. VM-тесты не проверяют web-точку
входа, выбор окружения JavaScript/Wasm и DOM-событие `beforeunload`.
Правило и границы покрытия описаны в
[руководстве тестирования](../doc/testing.md#браузерные-проверки).

Если после исправления обработчика стек ошибки по-прежнему указывает на старую
строку или выражение, выполните полный Restart отладки (Stop → Start) из
каталога `config_app`. Hot reload сохраняет состояние работающего приложения;
при диагностике важно проверить, что запущен именно текущий checkout.
Для панели, которую отдаёт отдельный web-сервер или фоторамка, изменение
`lib/` не обновляет обслуживаемую сборку: нужно обновить её на этом сервере.

Для release-сборки используйте `./build_linux.sh --release`.
Скрипт проверяет инструменты, GTK и mpv/epoxy, очищает нативный CMake-кэш,
выполняет `flutter pub get` и сборку. Обновление путей GTK также работает
при обычном `flutter build linux` и запуске из VS Code.

## Проверки видео

[Распределение покрытия, общие fake-зависимости и замер времени тестов](../doc/testing.md).

Unit/widget-тесты проверяют загрузку, паузу, перемотку, ошибки, таймауты,
смену URL, скрытие панелей, закрытие во время загрузки и освобождение контроллеров.
Полный набор проверок панели:

```sh
flutter test --no-pub
```

Проверки подготовки фото, повторения пары, кешированных входов и освобождения
ресурсов фотопредпросмотра, в том числе при недоступном frontend, отдельно:

```sh
flutter test --no-pub test/asset_photo_slide_session_test.dart \
  test/slideshow_preview_test.dart
```

Локализации RU/EN хранятся в ARB и обновляются штатным генератором из `i18n/`;
команды — в [README локализаций](../i18n/README.md).

Исторические исходники, сборки и [OpenGL backbuffer capture](../benchmarks/tool/egl_capture/README.md)
сохранены в архиве для воспроизводимости результатов. Локальные widget-тесты и
браузерный предпросмотр не заменяют проверку native compositor на RaPi5.

Функциональный тест Linux использует настоящий libmpv и MP4 через локальный
HTTP-сервер. Он проверяет воспроизведение и native texture, паузу, перемотку,
ошибочный URL и освобождение плееров. Путь к MP4 обязателен; без него тест
пропускается. Из `config_app`:

```sh
flutter test --no-pub -d linux integration_test/linux_video_test.dart \
  --dart-define=VIDEO_SMOKE_FILE="$(realpath ../benchmarks/assets/media/video_a.mp4)"
```

На машине без дисплея этот же тест можно запустить через
`LIBGL_ALWAYS_SOFTWARE=1 GDK_BACKEND=x11 xvfb-run -a flutter test ...`.
Это функциональная проверка desktop-плеера, а не измерение производительности
фоторамки; renderer и runtime RaPi5 она не проверяет.

Зависимости, причины ошибок `PkgConfig::GTK` и GSettings, способы диагностики
и порядок переноса исправления в другие приложения описаны в
[инструкции по Linux-сборке](../doc/linux-build-troubleshooting.md).

[Новые эффекты и Ken Burns](../doc/new-visuals-2026-10.md): настройка, совместимость,
предпросмотр, тесты и измерения на RaPi5.

[Тридцать дополнительных переходов в стиле видеоредакторов](../doc/premiere-style-transitions.md):
новые переходы в настройках и предпросмотре, совместимость и локальные проверки.
