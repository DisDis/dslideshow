# config_app

Web release собирается через `./build_web.sh`: скрипт получает зависимости и
останавливается при отказе `pub get`. Если зависимости уже подготовлены,
используйте `./build_web.sh --no-pub`. Именно этот режим использует
[`deb_factory/build.sh`](../deb_factory/readme.md), запуская web-сборку параллельно
AOT и проверкам; менять зависимости во время такого запуска нельзя.

По умолчанию web release собирается с `--wasm`: Dart-код и renderer `skwasm`
используют WebAssembly в поддерживаемом браузере. Flutter также сохраняет
JavaScript/CanvasKit fallback; bootstrap и взаимодействие с браузером остаются
на JavaScript. `--no-web-resources-cdn` сохраняет ресурсы renderer в bundle.
Выбор web-окружения использует `dart.library.js_interop` и работает как с Wasm,
так и с JavaScript. Выходной каталог — `build/web`; при развёртывании копируйте
его целиком, включая `main.dart.wasm`, `main.dart.mjs` и `canvaskit/`.

Для многопоточного `skwasm` серверу нужны HTTPS (либо localhost),
`Cross-Origin-Opener-Policy: same-origin` и
`Cross-Origin-Embedder-Policy: credentialless` (либо `require-corp`).
Штатный HTTP-сервер фоторамки эти заголовки не добавляет: используется
однопоточный `skwasm`, без требования менять сервер для запуска панели.
Поддержка браузеров и ограничения — в
[документации Flutter](https://docs.flutter.dev/platform-integration/web/wasm).

Для сборки нужен Flutter 3.47+ / Dart 3.13+.

* [Панель настройки](../doc/config-app.md): навигация, язык/тема, черновик,
  Save/Reload, защита ввода, WebSocket/RPC и визуальный предпросмотр.

  RPC-очереди, пауза/меню/экран и диагностика задержек.

  37 семейств, 82 пресета, длительность и воспроизведение фотопары.
* [Специальные экраны](../doc/special-screens.md): редактор часов и камер,

## Linux desktop

Из папки `config_app`:

Для видео в Linux desktop используются media_kit и системный libmpv.
Помимо GTK и инструментов сборки нужны заголовки и библиотеки:

```sh
sudo apt-get install libmpv-dev libepoxy-dev
```

```sh
./build_linux.sh --debug
flutter run -d linux
```

После добавления нативных зависимостей выполните полную пересборку и
Stop → Start отладки: Hot reload не регистрирует новый Linux-плагин.
Для запуска перенесённого bundle требуется системная библиотека libmpv
(в актуальном Debian/Ubuntu — пакет `libmpv2`).

В галерее поддерживаются запуск, пауза и перемотка видео; первый запуск
плитки начинается по нажатию, полноэкранный просмотр — автоматически. До запуска
плитка показывает серверный JPEG-постер через общий загрузчик миниатюр; на
платформе без плеера постер также доступен. Настройки генерации находятся в
`gallery` конфигурации рамки и применяются после её перезапуска.
Нажатие на изображение видео скрывает или показывает панели просмотра;
скрытые панели не блокируют кнопки плеера и перемотку.
Ошибки загрузки и инициализация дольше 15 секунд показывают локализованное
сообщение. Закрытие, смена файла и поздние ответы не запускают старое видео.
Если backend недоступен, контроллер не создаётся и панель показывает
ограничение платформы. Linux-плеер рассчитан на видеофайлы с известной
длительностью; live-потоки без длительности завершаются таймаутом инициализации.

В Web продолжает использоваться `video_player_web`: Linux/FFI-код подключается
условно и не входит в браузерную ветку. Форматы и autoplay зависят от браузера.
Проверка сборки из `config_app`:

```sh
./build_web.sh --no-pub
```

Автоматические браузерные тесты удалены из-за стоимости компиляции и запуска
Chrome. Обычные unit/widget-тесты выполняются в VM; браузерные тесты пишем
и запускаем только с согласия пользователя. VM-тесты не проверяют web-точку
входа, выбор окружения JavaScript/Wasm и DOM-событие `beforeunload`.
Правило и границы покрытия описаны в
[руководстве тестирования](../doc/testing.md#браузерные-проверки).

Если после исправления обработчика стек ошибки по-прежнему указывает на старую
строку или выражение, выполните полный Restart отладки (Stop → Start) из
каталога `config_app`. Hot reload сохраняет состояние работающего приложения;
при диагностике важно проверить, что запущен именно текущий checkout.
Для панели, которую отдаёт отдельный web-сервер или фоторамка, изменение
`lib/` не обновляет обслуживаемую сборку: нужно обновить её на этом сервере.

Для release-сборки используйте `./build_linux.sh --release`.
Скрипт проверяет инструменты, GTK и mpv/epoxy, очищает нативный CMake-кэш,
выполняет `flutter pub get` и сборку. Обновление путей GTK также работает
при обычном `flutter build linux` и запуске из VS Code.

## Проверки видео

[Распределение покрытия, общие fake-зависимости и замер времени тестов](../doc/testing.md).

Unit/widget-тесты проверяют загрузку, паузу, перемотку, ошибки, таймауты,
смену URL, скрытие панелей, закрытие во время загрузки и освобождение контроллеров.
Полный набор проверок панели:

```sh
flutter test --no-pub
```

Проверки подготовки фото, повторения пары, кешированных входов и освобождения
ресурсов фотопредпросмотра, в том числе при недоступном frontend, отдельно:

```sh
flutter test --no-pub test/asset_photo_slide_session_test.dart \
  test/slideshow_preview_test.dart
```

Локализации RU/EN хранятся в ARB и обновляются штатным генератором из `i18n/`;
команды — в [README локализаций](../i18n/README.md).

Исторические исходники, сборки и [OpenGL backbuffer capture](../benchmarks/tool/egl_capture/README.md)
сохранены в архиве для воспроизводимости результатов. Локальные widget-тесты и
браузерный предпросмотр не заменяют проверку native compositor на RaPi5.

Функциональный тест Linux использует настоящий libmpv и MP4 через локальный
HTTP-сервер. Он проверяет воспроизведение и native texture, паузу, перемотку,
ошибочный URL и освобождение плееров. Путь к MP4 обязателен; без него тест
пропускается. Из `config_app`:

```sh
flutter test --no-pub -d linux integration_test/linux_video_test.dart \
  --dart-define=VIDEO_SMOKE_FILE="$(realpath ../benchmarks/assets/media/video_a.mp4)"
```

На машине без дисплея этот же тест можно запустить через
`LIBGL_ALWAYS_SOFTWARE=1 GDK_BACKEND=x11 xvfb-run -a flutter test ...`.
Это функциональная проверка desktop-плеера, а не измерение производительности
фоторамки; renderer и runtime RaPi5 она не проверяет.

Зависимости, причины ошибок `PkgConfig::GTK` и GSettings, способы диагностики
и порядок переноса исправления в другие приложения описаны в
[инструкции по Linux-сборке](../doc/linux-build-troubleshooting.md).

[Новые эффекты и Ken Burns](../doc/effects.md): настройка, совместимость,
предпросмотр, тесты и измерения на RaPi5.

[Тридцать дополнительных переходов в стиле видеоредакторов](../doc/effects.md#визуальные-варианты):
новые переходы в настройках и предпросмотре, совместимость и локальные проверки.
