# Первичная проверка эффектов и native-отказы, 25.10.2026

Статус: историческое исследование; перенос и сверка документации — 29.10.2026.

## Исторические измерения и диагностика

Первичная диагностика 25 октября 2026 на Pi 5 (2 GB RAM, Linux 6.12.47):

* Подтверждён физический вывод 2560×1600, DPR=1, фактическая частота около 50 Hz.
* OpenGL: захват композиции подтвердил движение обоих H.264-видео.
* Фото-переходы выполняются через OpenGL и Vulkan, кадровая телеметрия поступает.
* В текущем нативном стеке обнаружены `MissingPluginException` при отмене
  видеоподписки и SIGSEGV во время тестирования двух видео в OpenGL.
* Vulkan сообщает отсутствие `VK_KHR_external_semaphore_fd`; процесс получает
  SIGSEGV при первом тесте с видео. С учётом подтверждённого автором отсутствия
  видеопути в установленном embedder это запуск неподдерживаемого сценария, не регрессия эффектов.
* Launcher доработан: сохраняет активный случай и данные до cleanup,
  после native crash продолжает smoke/standard со следующего случая.
  Ошибки не превращаются в успешные результаты.

В таблице сохранены фактические аварии исторического прогона. Для Vulkan
237 видеосценариев находятся вне поддерживаемых возможностей; все **249/249

Полнота обхода не означает успешную приёмку стабильности:

* **OpenGL:** все 79 фото→видео и 79 видео→фото прошли три повтора.
  В видео→видео завершены 29/79 сценариев; остальные 50 получили SIGSEGV.
  Последний активный сценарий — контекст аварии, а не доказательство причины.
  Сохранены также 89 ошибок `MissingPluginException` при cancel видеоподписки.
* **Vulkan:** все 237 сценариев с видео упали до первого measured-повтора.
  Они классифицированы как неподдерживаемые; фактические exit 139 в исходных
  данных сохранены. Все 249 фото/GIF/больших фото и stall-проб завершены.
  Предупреждение об отсутствии `VK_KHR_external_semaphore_fd` есть в native.log;
  его причинная связь с конкретным SIGSEGV не устанавливалась.
* **Физический вывод видео:** пользователь подтвердил, что видел видео на
  экране фоторамки во время прогона. Режим и конкретные сценарии неизвестны.
  Это отдельное ручное подтверждение вывода; его нельзя приписывать Vulkan
  или использовать как проверку каждого эффекта. В OpenGL захваты композиции
  отдельно подтвердили движение обеих видеотекстур.
* **Контроллер:** во всех 2083 measured-повторах и 714 прогревах прогресс
  монотонный, максимальный шаг около 0.01. Все 18 блокировок UI на 80 ms
  выполнены без скачка прогресса. При ~50 кадрах/с переход на 1000 ms штатно
  занимает около 2 s из-за ограничения продвижения времени; это допустимо.
* **Мозаики на фото в OpenGL:** шесть вариантов, Canvas и shader,
  100×100–200×200 — около 2.10–2.12 s, примерно 48–49 Flutter кадров/с.
  Четырёхкратное увеличение числа ячеек не ухудшило заметно общий темп.
  Для MosaicFade UI p95 одного повтора: Canvas 100×100 — 1.483 ms,
  Canvas 200×200 — 5.169 ms, shader 200×200 — 0.105 ms.
  На полном фото 8000×6000 общий результат также около 2.1 s;
  подготовка оригинала отдельно занимает медианно 989 ms в OpenGL.
* **Shader не универсально быстрее:** для шести пар мозаик OpenGL на 100×100
  среднее отношение длительностей shader/Canvas даёт +18.2% для фото→видео
  и +6.3% для видео→фото; на 200×200 — −8.1% и −11.2% соответственно.
  Canvas остаётся default до сбалансированного A/B и визуальной проверки.
* **Дорогие эффекты:** на фото→фото OpenGL ZoomOver занимает 8.14 s,
  BlurFade 5.17 s, Accordion/LiquidMorph 4.04 s при номинале 1 s.
  У ZoomOver видео→фото один переход занял 14.22 s, с паузой между
  Flutter кадрами до 3.10 s и raster duration до 3.02 s.
  Ограниченный шаг прогресса не устраняет такие паузы между кадрами.
* **Память:** в OpenGL MemAvailable опускался до 128.8 MiB рядом с
  ZoomOver видео→фото, SwapFree — до 92.6 MiB. Наблюдается давление на
  память; утечка или причина SIGSEGV этим не доказаны. RSS не охватывает
  все GPU/decoder allocations. Все снятые throttle_bits равны 0.
* **Сравнение renderer:** на 249 совпавших полных сценариях без видео
  медиана отношения длительностей Vulkan/OpenGL — 1.496. Режимы шли
  последовательно, governor ondemand; вывод ограничен данной установкой.
  Исходной старой реализации в этом прогоне нет, выигрыш оптимизаций
  относительно неё не измерен.

При разборе сырых данных обнаружены ограничения самого стенда:

1. Шесть `StreamSink is bound to a stream` в `ReportStore.telemetry`:
   запись пересекается с `flush`; часть опросов могла потеряться.
2. Checkpoint не включает 28 уже сохранённых measured-повторов из 17
   аварийных сценариев. В отдельном анализе они учтены как частичные;
   в сравнения полных сценариев не входят.
3. Асинхронные ошибки cleanup попадают в `errors.jsonl`, но не всегда
   увеличивают `failed_runs` конкретного случая. Приёмка учитывает оба файла.
4. Flutter vsync timestamps кратны примерно 16.667 ms при режиме дисплея
   около 50 Hz. `estimated_missed_vsyncs` не следует трактовать как число
   пропусков физического дисплея. FPS — оценка по Flutter кадрам;
   raster duration включает native renderer/present ожидания, не только GPU.

Старые full-standard и его производный анализ удалены при очистке 29.10.2026.
Исторические числа и ограничения сохранены выше; уникальные native-ошибки
перенесены в материалы [видеоисследования](../flutter-pi-video-2026-10-25/README.md).
Состав оставшихся архивов описан в [индексе отчётов](../README.md).
Эти данные не служат baseline для нынешнего каталога и native runtime.

### Исправления стенда и проверка геометрии

* Записи JSONL и flush сериализованы, включая timer-driven телеметрию и ошибки.
  Тест сохраняет все записи при пересекающихся flush.
* Агрегация восстанавливает сырые measured-повторы, успевшие записаться после
  checkpoint; исторический архив даёт 1336 повторов и 135153 кадров OpenGL,
  включая ранее пропущенные 28 повторов.
* Runtime/cleanup/capture/telemetry ошибки имеют отдельные счётчики и влияют
  на `successful`; неподдерживаемые сценарии не создают фиктивные измерения.
* Vsync-оценка становится null, если Flutter timestamps не согласованы с
  периодом дисплея. Фото/GIF и обе мозаики сохраняют исходное качество.
* Перед initialize/play/seek/dispose пишется `active-operation.json`.
  Основное приложение не содержит benchmark-инструментации.
* Добавлен короткий `config/visual.json`: 21 контрольный кадр каждого эффекта,
  эталоны A/B, проверка изменяемости/начального/конечного кадра, HTML просмотра.
  Прозрачный/неинформативный readback отмечается `unverified_capture`.
* Контрольная фаза подписана на экране. Старый capture показывал неподвижные
  0/50/100%; у Diagonal середина — треугольник B, поэтому последовательность
  могла выглядеть как описанное пользователем дискретное появление полигонов.
  Без записи конкретного наблюдения это остаётся вероятным объяснением.
* Плотная локальная проверка обнаружила раннее наложение B в Tablet/Zoom Out:
  translation применялся в уже масштабированной/повёрнутой системе координат.
  Порядок исправлен. В Cube/Tablet/Flip перспектива нормирована по размеру
  вращаемой стороны (прежняя сила на 320 px), чтобы на 2560×1600 вершины
  не пересекали плоскость камеры. 48 эффектов × 21 кадр × два размера проходят
  проверки конечных состояний, изменяемости и положительной глубины углов.

### Native OpenGL: исходная гипотеза и границы

На этом этапе пользователь запретил изменять и устанавливать flutter-pi.
`/opt/dslideshow/flutter-pi` сохранён, SHA256:
`e1b6b7d263b4cd4962770542a40f430ea3b2f4bd0fe4ed552ecf1ddcccb418b7`.
ОС, драйверы и прошивка не обновлялись. До этого уточнения эксперимент выполнялся
только в отдельной копии исходников под каталогом `benchmarks/native` на устройстве;
эта копия не используется рабочей службой и в пакет стенда не включается.

* На исходном native runtime и отдельной неизменённой сборке с символами
  воспроизведён SIGSEGV уже на **Baseline video→video**, до участия эффекта.
* Стек: `libgallium-24.2.8` → `libgbm` → `dup_gst_memory_as_dmabuf` →
  `frame_new` → `on_appsink_new_sample`. Дизассемблирование указывает на
  `gbm_bo_unmap`. Исходники flutter-pi: `129b07481d7607fbc41cfe4057fa348993d36a66`.
* Гипотеза: конкурирующие software uploads двух плееров используют общий GBM
  mapping context без общей блокировки; per-player context lock этого участка
  не охватывает. Экспериментальная сериализация прошла 20 measured-повторов
  Baseline/Cube/Fade/Blinds без SIGSEGV, однако ошибки cancel/старого стенда
  остались. Это ограниченное подтверждение гипотезы, не production-приёмка.
* Автономный GBM stress без полного Flutter/texture lifecycle аварии не вызвал
  ни в параллельном, ни в последовательном режиме. Он не заменяет reproducer
  в реальном плеере; причинность требует дальнейшей проверки.

На 25 октября были предложены следующие продолжения; их последующее состояние
описано в видеоисследовании и актуальном плане, а не задаётся этим списком:

1. Повторить A/B на том же runtime с полной цепочкой EGL/GBM, подтвердить гонку
   и выбрать минимальную блокировку/раздельные upload contexts.
2. Проверить buffer/sample lifetime и `gst_sample_is_writable` при seek.
3. Проверить порядок listen/cancel/dispose и поздние cancel после удаления
   event channel. Не подавлять MissingPluginException ради успешного отчёта.
4. Отдельно оценить интеграцию Vulkan texture callback из нового API Flutter:
   версии engine/header, импорт VkImage, layout, синхронизацию и освобождение.
   Наличие API движка не означает готовую реализацию во flutter-pi.
5. Сохранять рабочий runtime, проверять отдельный бинарник; установка/замена
   рабочего runtime в текущие работы не входит.

### Короткая проверка композиции и возможностей

Короткая аппаратная проверка завершена: `20261025T072940Z-smoke-lYXNBYsz`.
В OpenGL и Vulkan по 55 сценариев: 54 успешных проверки вариантов эффектов
и один неподвижный Baseline-эталон. Всего 2310 контрольных кадров; у каждого
эффекта не менее 19 разных кадров из 21, конечный кадр совпадает с B.
Native crash и событий ошибок нет, оба процесса и launcher завершились с 0.
Это проверка композиции и геометрии; частота физического scanout отдельно
не измерялась. Номинал 500 ms, один повтор без прогрева — этот прогон не
используется для выводов о приросте производительности относительно standard.

Финальная сборка стенда также проверена на устройстве: видео Vulkan по
умолчанию и при `--no-vulkan-video` поверх JSON opt-in получает `unsupported`
до создания плеера. В обоих случаях ноль измерений/падений/ошибок, exit 0.

и visual-device-check удалены при очистке 29.10.2026; выводы этого исторического
